# ХПИИ — сторож публикаций

Независимый **непубликующий** GitHub Actions workflow: [HPII — watchdog (no publishing)](../.github/workflows/hpii-watchdog.yml). Запускается ежечасно на минуте 13 UTC; запуск GitHub Actions может задерживаться.

Проверяет:

- Не остановился ли планировщик `site-first-scheduled-release.yml` (допустимая задержка 85 минут) и не завершился ли его последний значимый запуск ошибкой.
- Не остановился ли `Dzen to Telegram` в публичном репозитории `AfterDark1000/dzen-telegram-crosspost` (допустимая задержка 155 минут) и не завершился ли последний запуск ошибкой. `New articles: 0` — штатная ситуация.
- Если готовые материалы в `editorial-intake` уже можно выпускать (с учётом момента готовности, отложенного `site_publish_at` и 60-минутного интервала) и они ждут больше 100 минут после разрешённого времени — отклонение.
- Открывается ли последний уже выпущенный материал на `iipike.ru` после 45-минутной паузы на GitHub Pages.

При отклонении создаёт **одну** GitHub Issue `[HPII WATCHDOG] <компонент>` и упоминает владельца. Пока проблема сохраняется, новых Issues и повторных упоминаний не создаёт; после восстановления закрывает её с записью. История сбоев доступна в [Issues](https://github.com/AfterDark1000/iipike-site/issues?q=is%3Aissue+%22HPII+WATCHDOG%22). Для email/push-уведомлений нужно, чтобы GitHub-аккаунт владельца получал уведомления об упоминаниях (Settings → Notifications). Если GitHub API недоступен, сторож фиксирует именно ошибку диагностики, **не** утверждает, будто публикации остановились.

**Что НЕ проверяет:** достоверную доставку Repostbot в MAX. У MAX/Repostbot нет проверенного внешнего read-only интерфейса для подтверждения истории; успешный Telegram workflow не доказывает публикацию в MAX. Пока доступно только ручное сравнение `@iipike` и `max.ru/channel_iipike`. Впоследствии можно добавить проверку по официальному API или отчёту самого репостера.

Сторож не запускает релизы, не публикует тестовые посты, не меняет обложки, сайт или секреты. `GITHUB_TOKEN` имеет только `contents:read`, `actions:read`, `issues:write`. Никаких дополнительных секретов не требуется.

Проверка после включения: сначала `Run workflow` вручную; убедиться в прохождении тестов и разделе Summary, затем посмотреть Issues. Не делать тестовые публикации ради проверки уведомлений.
