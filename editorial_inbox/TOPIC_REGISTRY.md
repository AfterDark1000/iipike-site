# ХПИИ — самостоятельная регистрация новых тем редактором

**Кто создаёт:** основной редактор ChatGPT, работающий с подтверждённой новостью и подключённым GitHub. Отдельное согласование с человеком **не требуется для технического расширения справочника**. Публикация новости по-прежнему требует «берём» и готовую обложку.

**Что не меняется:** четыре рубрики; уже опубликованные статьи и их даты; постоянные адреса существующих тем. Тема — дополнительная кликабельная навигация, не редакционная рубрика.

## Что считается основанием

Редактор проверяет соответствие сюжета существующим темам в `scripts/site_topics.py` и архиве `news.json`. Отдельное направление может появиться при **двух или более независимых подтверждённых историях** (из опубликованного архива и/или текущей подборки с первоисточниками). Два пересказа одной новости не считаются независимыми. Тема должна быть пригодна для последующих публикаций, иметь понятные границы и отличаться по содержанию от действующих категорий. Не создавать темы ради единственного продукта, имени или журналистской шутки.

## Единственный способ регистрации

Из текущего `main` создать рабочую ветку; в ней **только дописать** новый элемент массива в `data/topic_extensions.json`. Не изменять Python, исходные статьи или уже существующие объекты. Сам реестр начинает работу с пустого списка:

```json
{
  "schema_version": 1,
  "topics": []
}
```

Один пример нового элемента (иллюстрация **формата**, не призыв создавать эту тему):

```json
{
  "key": "virtual-worlds",
  "name": "Виртуальные 3D-миры",
  "description": "Создание интерактивных трёхмерных миров и игровых сред с помощью ИИ.",
  "why_not_existing": "Речь о создании управляемой трёхмерной среды, а не только о генерации видеороликов или статических картинок.",
  "evidence": [
    {"source_url": "https://example.org/first-primary-source"},
    {"source_url": "https://example.org/second-independent-primary-source"}
  ]
}
```

В реальной заявке `example.org` **недопустим как доказательство**: редактор обязан подставлять только проверенные первоисточники. Можно ссылаться на уже опубликованную статью: `{"article_id": "точный-id-из-news.json"}`. Примеры должны относиться к разным реальным событиям. Ограничения в коде: два–шесть примеров; безопасные HTTPS-адреса или существующие ID, отдельный уникальный латинский ключ, название, точное описание и содержательное отличие от существующих тем.

Далее:

1. Открыть PR в `main`, пояснить фактическую необходимость темы и привести подтверждения.
2. Дождаться **зелёных CI** (включая тесты реестра, проверки сайта и запрет изменения старых элементов). Сбой — исправить PR, без тихого обхода проверки.
3. Редактор **сам объединяет** прошедший проверки PR. Это не публикация новости.
4. Убедиться, что завершился workflow `HPII — upgrade article navigation and topic pages`: создана страница `/topics/<key>/`, прошли тесты и Pages. Не создавать страницы вручную.
5. После появления реального ключа в `main` сохранить утверждённую новость в обычный `editorial-intake` с `topics: ["<key>"]`. После её публикации тема автоматически появляется в каталоге и становится индексируемой. Пустая тематическая страница помечена `noindex`.

Если PR/CI/Pages не завершились успешно, не утверждать, что тема зарегистрирована. Статью можно выпустить с уже существующими **подходящими** темами или с `topics: []`; никогда не вписывать произвольный несуществующий ключ ради выпуска.

## Безопасность и постоянство

- Чтение справочника: `TOPICS` включает 17 встроенных разделов плюс валидированные пользовательские расширения из `data/topic_extensions.json`.
- Реестр **строго дописывается**. Изменить или удалить старый элемент обычным PR нельзя: старый ключ является публичным URL.
- Базовые темы и существующие материалы не переклассифицируются при появлении новой темы.
- `scripts/check_topic_registry.py --base-sha <sha>` проверяет неизменность реестра относительно ветки назначения; `tests/test_site_topic_registry.py` проверяет ошибки, инъекции, дубли и создание страниц.
- Два технически различных URL ещё не доказывают смысловую независимость и качество темы: это **ответственность редактора**, который проверяет источники и архив.
- Если новое направление единичное или доказательства слабы, редактор предлагает название для будущего, но **не регистрирует** его.
