# Asahi Linux меняет лицензию из-за «отмывания» кода через ИИ

Разработчики **Asahi Linux** решили ужесточить условия использования своего кода после того, как, по их словам, сторонние проекты начали присваивать их наработки, иногда скрывая заимствования с помощью нейросетей. 7 ноября команда объявила о начале перехода на лицензию **GPLv2+**.

Asahi Linux занимается адаптацией Linux для компьютеров Apple с процессорами серии M. Значительную часть работы приходится выполнять практически с нуля: изучать устройство оборудования, писать драйверы и добиваться совместимости с системой.

Проект ведёт разработку открыто. Доступны даже личные рабочие ветки программистов, где находятся ещё не законченные функции.

Именно этим, как утверждает команда, воспользовались некоторые сторонние разработчики. Они забирали незавершённый код и публиковали его в собственных проектах без указания авторства. В отдельных случаях заимствованные фрагменты переписывали с помощью больших языковых моделей (LLM), чтобы замаскировать их происхождение.

Прежде Asahi Linux старалась распространять как можно больше собственного кода под свободной лицензией **MIT**. Такой выбор был сознательным: авторы хотели, чтобы их разработки могли использовать другие открытые операционные системы, включая семейство BSD.

MIT позволяет включать чужой открытый код даже в коммерческие программы с закрытыми исходниками. Необходимо лишь соблюдать предусмотренные лицензией условия, в том числе сохранять уведомления об авторских правах.

Теперь команда начинает переводить свои репозитории на **GNU GPL версии 2 или более поздней**. Она тоже разрешает коммерческое использование и продажу программ, но при распространении производной версии требует предоставлять соответствующий исходный код на условиях GPL. Создать закрытый коммерческий продукт на основе таких разработок становится гораздо сложнее.

В качестве исторического примера авторы Asahi Linux вспоминают **Wine** — программу, позволяющую запускать Windows-приложения в других операционных системах. Первоначально Wine тоже распространялась под MIT, но появление множества закрытых коммерческих ответвлений заставило разработчиков пересмотреть подход. В 2002 году проект перешёл на LGPL.

У самой Asahi Linux отношения с генеративным ИИ и без того непростые. Её внутренняя политика запрещает использовать LLM для существенных вкладов в разработку. Одна из причин — риск попадания чужого закрытого кода в проект, который изучает оборудование Apple методами независимой обратной разработки. За сокрытие масштабного использования нейросетей участника могут исключить из проекта.
