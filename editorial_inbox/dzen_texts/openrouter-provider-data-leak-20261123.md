# Ваши секреты из чатов с ИИ могли попасть к хакерам: OpenRouter отключила трёх поставщиков

Хакеры перехватывали запросы к нейросетям и пытались использовать найденные в них секретные ключи, даже когда пользователи включали режим повышенной конфиденциальности.

22 ноября **OpenRouter**, сервис для доступа к моделям разных разработчиков, объявил об отключении трёх поставщиков ИИ.

Ещё 125 точек доступа к моделям лишились статуса **Zero Data Retention (ZDR)**, который предполагает отсутствие хранения пользовательских запросов и ответов.

Причиной стало расследование специалистов по кибербезопасности из **Dragos**.

## 🪤 Два миллиона запросов с секретной начинкой

Исследователи с июля по ноябрь отправили нейросетям почти **два миллиона специально подготовленных запросов**.

Внутри прятались уникальные ссылки и подставные ключи доступа к облачным сервисам Amazon.

После отправки оставалось наблюдать, кто попытается открыть эти ссылки или воспользоваться ключами.

**И приманка сработала.**

Специалисты обнаружили признаки взлома инфраструктуры как минимум трёх поставщиков ИИ.

Посторонние получали содержимое запросов и пытались использовать найденные ключи для доступа к облачным ресурсам.

В общей сложности злоумышленники выполнили **десятки тысяч обращений к AWS** с использованием подставных ключей.

Причём в одном из случаев перехватывались даже запросы, которые поставщик отклонил ещё до запуска нейросети.

Это означает, что данные копировались уже на входе в инфраструктуру компании.

## 🔓 Галочка «Не сохранять» не спасла

В двух из трёх случаев взлома среди похищенных запросов оказались сообщения с включённым режимом Zero Data Retention.

Исследователи обнаружили и другой способ получить чужие данные.

Некоторые продавцы доступа к нейросетям предлагали модели по низкой цене, включали журналирование запросов и получали возможность читать сообщения клиентов.

Для этого даже не требовалось взламывать систему.

В отдельных случаях запросы, отправленные американским поставщикам, попадали к китайским ИИ-компаниям вопреки заявленным правилам обработки данных.

**Некоторые секретные ссылки открывали спустя месяцы после единственного обращения к модели.**

## 🚫 OpenRouter начала отключения

После расследования OpenRouter исключила трёх поставщиков из своей платформы и пересмотрела статус конфиденциальности 125 точек доступа.

Часть ограничений ввели профилактически, пока проверяют соблюдение правил.

Потенциально пострадавших клиентов уведомили.

Компания намерена регулярно проводить проверки с подставными секретами и выяснять, каким сторонним организациям поставщики передают запросы.

Саму инфраструктуру OpenRouter исследователи взломанной не обнаружили.

**Главная проблема оказалась дальше по цепочке:** пользователь отправлял запрос через один сервис, а обрабатывать его могли другие компании со своими системами хранения и защиты данных.

Именно на этих участках и обнаружились утечки.
