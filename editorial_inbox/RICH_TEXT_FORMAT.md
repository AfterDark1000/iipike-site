# ХПИИ: оформление статьи редактора → сайт без потерь

Этот формат используется **тем же рабочим редактором ChatGPT**, который готовит статьи для Дзена. Не требуется писать вторую версию: при команде «берём» передаём **полный текст и его структуру**, а генератор `iipike.ru` создаёт HTML.

## Новый стандарт: одна дословная статья, без повторной JSON-разметки

Начиная со следующей утверждённой новости редактор после «берём» сохраняет **ровно тот Markdown, который уже был показан и утверждён человеком**, в поле `article_markdown` файла `editorial_inbox/stories/<id>.json`. Никаких переписанных блоков `paragraphs` для новых статей. В JSON заголовок хранится отдельно в `title`/`dzen_title`, поэтому `article_markdown` начинается с первого абзаца и **не содержит дублирующего заголовка H1**.

Пример дословной статьи для поля `article_markdown`:

~~~markdown
Компания объявила **важное изменение**. Оно касается нескольких процессов.

## Что известно

Подробности появились в [первоисточнике](https://example.org/news).

- Первый проверенный результат.
- Второй *важный* результат.

> Это слова официального представителя.
> — Автор заявления

### Что будет дальше

1. Проверка.
2. Публикация.

Итог: даты запуска пока не объявлены.
~~~

Поддерживаются `##` и `###` как подзаголовки, обычные абзацы, `**жирный**`, `*курсив*`, HTTPS-ссылки, `-`/`*` списки, `1.` нумерованные списки и строки `> ` для цитат; последняя строка `> — Автор` становится атрибуцией цитаты. Первая строка обычного текста автоматически становится выделенным вступлением. Порядок и содержание сохраняются, HTML создаётся на сайте, а исходный Markdown хранится рядом с опубликованной статьёй для проверки соответствия.

Неподдерживаемые заголовки `#`/`####`, блоки кода и разделители `---` отклоняются при проверке вместо молчаливой потери разметки. Не добавляй выделения, которых не было в утверждённой версии. Таблицы Markdown поддерживаются в формате ниже. Иллюстрации внутри статьи поддерживаются в строго проверенном формате ниже.

## Таблицы внутри статьи

Обычная Markdown-таблица с заголовком, строкой разделителей и данными:

~~~markdown
| Модель | Цена | Результат |
| --- | ---: | :---: |
| **A** | 10 $ | 75 % |
| B | 20 $ | 80 % |
~~~

Отделяйте таблицу пустыми строками от соседних абзацев. В каждой строке одинаковое число ячеек; пустые ячейки допустимы. В заголовках разделителей минимум три дефиса, двоеточия управляют выравниванием. Для символа вертикальной черты внутри ячейки используйте `\\|`. Поддерживаются обычные выделения и безопасные HTTPS-ссылки. 1–12 столбцов, 1–100 строк данных, до 2000 символов в ячейке. Сайт сам создаёт HTML-таблицу и прокрутку на узких экранах; исходный Markdown не меняется. В Дзене перенос табличного оформления зависит от его редактора. В админке `/admin/` → «Для Дзена» → «Текст для Дзена» таблицы обнаруживаются в подготовленном Markdown автоматически. Кнопка «Скачать таблицу N» создаёт фирменный PNG локально в браузере, длинную таблицу сохраняет частями с повтором шапки в ZIP; при нескольких таблицах доступен общий ZIP. Текст и HTML сайта не меняются; в Дзене вставьте изображение вместо соответствующей таблицы. Никаких заданий художнику, внешних генераторов и новых обязательных этапов выпуска. Сырой HTML не нужен.

## Иллюстрации внутри статьи: безопасная привязка к ID

Иллюстрация задаётся **отдельной строкой** утверждённого `article_markdown`, после смыслового подзаголовка или абзаца:

~~~markdown
![Памятка: пять шагов проверки подозрительного звонка](illustrations/voice-deepfake-family-money-scam-guide-20261109/family-voice-deepfake-checklist.webp)
~~~

Оригинальные байты WebP/PNG/JPEG передаются отдельно в GitHub **на ветку `editorial-intake`** по пути `editorial_inbox/illustrations/<id>/<name>.<ext>`. Не используйте внешние URL, SVG, относительные `../`, HTML, data: или не принадлежащие статье файлы. Alt-текст обязателен. Допускается не более 24 дополнительных изображений на статью (обложка отдельно); файлы проходят проверку декодирования, расширения, размера и безопасных габаритов. Любая отсутствующая иллюстрация удерживает выпуск до загрузки.

При подготовке релиза исходные изображения копируются без изменений в `assets/editorial/inline/<id>/`; HTML-страница вставляет адаптивный `<figure>` с безопасным `<img>`. Порядок иллюстраций сохраняется. Исходный Markdown остаётся неизменным. Для Дзена изображение нужно загрузить вручную в отмеченном месте: простой текст Markdown не загружает бинарные вложения в редактор Дзена.

## Карусель связанных иллюстраций

Чтобы показать серию тематически связанных картинок в одном месте, поставьте две или больше обычных Markdown-иллюстраций подряд (пустая строка допустима, текстового абзаца между ними быть не должно):

~~~markdown
![Первый кадр: исходный вариант](illustrations/<id>/first.webp)
![Второй кадр: результат](illustrations/<id>/second.webp)
![Третий кадр: подробности](illustrations/<id>/third.webp)
~~~

Замените `<id>` на реальный ID статьи. Сайт сам объединяет соседние иллюстрации в карусель со стрелками, счётчиком, свайпами и открытием оригиналов. Alt-текст используется как подпись кадра. Без JavaScript остаётся обычная горизонтальная прокрутка. Автопрокрутки нет. Чтобы оставить изображения отдельно, разделите их относящимися к ним абзацами или подзаголовками. Одиночное изображение отображается как раньше. Все прежние проверки файлов и общий предел 24 дополнительных изображений действуют; отдельная схема или дополнительное задание художнику не нужны.

В RSS для Дзена изображения остаются отдельными; в админке все кадры доступны в прежней кнопке «Иллюстрации ↓» после публикации сайта (по отдельности или ZIP). При ручной публикации в Дзене сгруппируйте их его средствами, если доступны. Сайт не управляет каруселями Дзена.

## Прямые цитаты: единый текст для Дзена и сайта

Для короткой проверенной прямой речи применяй **отдельный блок Markdown**, а не кавычки внутри обычного абзаца. Формат (строки ниже — **образец разметки**, не реальная цитата):

~~~markdown
> Краткая дословная цитата или её точный перевод на русский язык.
> — Имя Фамилия, должность
~~~

**На сайте:** `article_markdown` сохраняется дословно; `markdown_to_blocks` распознаёт строки `> ` как цитату, а последнюю строку `> — ` — как атрибуцию, отображаемую в `<blockquote class="editorial-quote">` с отдельной подписью. CSS цитаты и мобильная адаптация уже существуют. Кавычки-ёлочки вокруг всей цитаты не требуются; сама принадлежность реплики обозначена блоком. Не добавляй `> ` к имени автора внутри обычных абзацев. Не используй пустые строки внутри единого блока цитаты.

**В Дзене:** при ручной вставке проверяй результат: редактор Дзена имеет встроенный стиль «Цитата» с вертикальной полосой слева, но автоматическое преобразование исходного Markdown при вставке **не гарантировано**. Выдели текст реплики и примени этот стиль, если он не перенесён; имя и должность укажи отдельной строкой после цитаты. Не оставляй буквальные знаки `>` в опубликованной статье. Наличие правильной HTML-разметки на сайте само по себе не подтверждает оформление в Дзене.

**Достоверность:** прямую речь цитируй только при наличии проверяемого оригинала; перевод не должен добавлять смысл, которого в оригинале нет, при необходимости обозначь язык перевода. Сокращения и купюры отражай явно. Не подменяй дословную цитату вольным пересказом, не выдумывай атрибуцию; ссылка на датированный источник остаётся в источниках статьи. Из внешних материалов бери только необходимый короткий фрагмент. Цитатный блок не обязателен, если достоверных или содержательных слов нет.

**Старый формат `paragraphs` ниже — исключительно для совместимости с архивными и уже принятыми материалами.** Редактор ChatGPT не должен переводить в него новые статьи. Такая ручная конвертация раньше теряла оформление.

## Что сохраняем

| Оформление | JSON при передаче на сайт | HTML сайта |
| --- | --- | --- |
| Начальный абзац | `{"type":"lead","text":"..."}` | Выделенный вступительный абзац |
| Обычный абзац | `{"type":"p","text":"..."}` | Абзац |
| Подзаголовок | `{"type":"h2","text":"..."}` | `<h2>` |
| Жирный фрагмент | `**текст**` внутри текстового поля | `<strong>` |
| Курсив | `*текст*` внутри текстового поля | `<em>` |
| Ссылка | `[подпись](https://example.org/page)` | Безопасная кликабельная ссылка |
| Список с маркерами | `{"type":"ul","items":["пункт 1","пункт 2"]}` | `<ul><li>…` |
| Нумерованный список | `{"type":"ol","items":["шаг 1","шаг 2"]}` | `<ol><li>…` |
| Цитата | `{"type":"quote","text":"…","attribution":"Автор"}` | `<blockquote>` и подпись автора |

### Пример полного поля paragraphs

```json
[
  {"type": "lead", "text": "Компания объявила **важное изменение**. Что это значит на практике?"},
  {"type": "p", "text": "Детали опубликованы в [первоисточнике](https://example.org/press-release)."},
  {"type": "h2", "text": "Что уже работает"},
  {"type": "ul", "items": ["Система получила **новую функцию**.", "Разработчики опубликовали технические подробности."]},
  {"type": "quote", "text": "Это *первый* результат нашей работы.", "attribution": "Представитель компании"},
  {"type": "h2", "text": "Что дальше"},
  {"type": "ol", "items": ["Тестирование", "Публичный выпуск"]},
  {"type": "p", "text": "Итог: сроки пока не названы."}
]
```

Первый блок **обязательно `lead`**, дальше можно перемешивать абзацы, подзаголовки, списки и цитаты в реальном порядке статьи. Пустые элементы запрещены. Не уплощай списки в один текст, не прибавляй к подзаголовку Markdown `##` — используй `type:"h2"`. Не добавляй `>` перед текстом цитаты — используй `type:"quote"`. `attribution` у цитаты необязателен, а не придуман.

**Важное ограничение:** в тексте поддерживается только небольшой набор Markdown (жирный, курсив и простые HTTPS-ссылки). Не вкладывай выделения друг в друга, не используй сырые HTML-теги, JavaScript-ссылки, встроенные плееры, внешние/произвольные изображения или произвольный Markdown. Неизвестные элементы отклоняются, HTML-строки выводятся как текст, а не выполняются. Источник по-прежнему отдельно в блоке «Первоисточник».

Оформление является **данными редактора**, а не HTML-кодом, который редактор мог бы выполнить на сайте. Структура сохраняется при `editorial_inbox/stories/<id>.json` → `content/approved/<id>.json` → готовой статье `articles/<id>/index.html`.

Не применять эту конвертацию к постам Threads/X и не переделывать исторический архив: изменения предназначены для новых полных статей, выпущенных сначала на сайте.
