# ХПИИ: оформление статьи редактора → сайт без потерь

Этот формат используется **тем же рабочим редактором ChatGPT**, который готовит статьи для Дзена. Не требуется писать вторую версию: при команде «берём» передаём **полный текст и его структуру**, а генератор `iipike.ru` создаёт HTML.

## Новый стандарт: одна дословная статья, без повторной JSON-разметки

Начиная со следующей утверждённой новости редактор после «берём» сохраняет **ровно тот Markdown, который уже был показан и утверждён человеком**, в поле `article_markdown` файла `editorial_inbox/stories/<id>.json`. Никаких переписанных блоков `paragraphs` для новых статей. В JSON заголовок хранится отдельно в `title`/`dzen_title`, поэтому `article_markdown` начинается с первого абзаца и **не содержит дублирующего заголовка H1**.

Пример дословной статьи для поля `article_markdown`:

~~~markdown
Компания объявила **важное изменение**. Оно касается нескольких процессов.

## Что известно

Подробности появились в [первоисточнике](https://example.org/news).

- Первый проверенный результат.
- Второй *важный* результат.

> Это слова официального представителя.
> — Автор заявления

### Что будет дальше

1. Проверка.
2. Публикация.

Итог: даты запуска пока не объявлены.
~~~

Поддерживаются `##` и `###` как подзаголовки, обычные абзацы, `**жирный**`, `*курсив*`, HTTPS-ссылки, `-`/`*` списки, `1.` нумерованные списки и строки `> ` для цитат; последняя строка `> — Автор` становится атрибуцией цитаты. Первая строка обычного текста автоматически становится выделенным вступлением. Порядок и содержание сохраняются, HTML создаётся на сайте, а исходный Markdown хранится рядом с опубликованной статьёй для проверки соответствия.

Неподдерживаемые заголовки `#`/`####`, блоки кода и разделители `---` отклоняются при проверке вместо молчаливой потери разметки. Не добавляй выделения, которых не было в утверждённой версии. Изображения внутри статьи и таблицы пока отдельно не поддерживаются.

**Старый формат `paragraphs` ниже — исключительно для совместимости с архивными и уже принятыми материалами.** Редактор ChatGPT не должен переводить в него новые статьи. Такая ручная конвертация раньше теряла оформление.

## Что сохраняем

| Оформление | JSON при передаче на сайт | HTML сайта |
| --- | --- | --- |
| Начальный абзац | `{"type":"lead","text":"..."}` | Выделенный вступительный абзац |
| Обычный абзац | `{"type":"p","text":"..."}` | Абзац |
| Подзаголовок | `{"type":"h2","text":"..."}` | `<h2>` |
| Жирный фрагмент | `**текст**` внутри текстового поля | `<strong>` |
| Курсив | `*текст*` внутри текстового поля | `<em>` |
| Ссылка | `[подпись](https://example.org/page)` | Безопасная кликабельная ссылка |
| Список с маркерами | `{"type":"ul","items":["пункт 1","пункт 2"]}` | `<ul><li>…` |
| Нумерованный список | `{"type":"ol","items":["шаг 1","шаг 2"]}` | `<ol><li>…` |
| Цитата | `{"type":"quote","text":"…","attribution":"Автор"}` | `<blockquote>` и подпись автора |

### Пример полного поля paragraphs

```json
[
  {"type": "lead", "text": "Компания объявила **важное изменение**. Что это значит на практике?"},
  {"type": "p", "text": "Детали опубликованы в [первоисточнике](https://example.org/press-release)."},
  {"type": "h2", "text": "Что уже работает"},
  {"type": "ul", "items": ["Система получила **новую функцию**.", "Разработчики опубликовали технические подробности."]},
  {"type": "quote", "text": "Это *первый* результат нашей работы.", "attribution": "Представитель компании"},
  {"type": "h2", "text": "Что дальше"},
  {"type": "ol", "items": ["Тестирование", "Публичный выпуск"]},
  {"type": "p", "text": "Итог: сроки пока не названы."}
]
```

Первый блок **обязательно `lead`**, дальше можно перемешивать абзацы, подзаголовки, списки и цитаты в реальном порядке статьи. Пустые элементы запрещены. Не уплощай списки в один текст, не прибавляй к подзаголовку Markdown `##` — используй `type:"h2"`. Не добавляй `>` перед текстом цитаты — используй `type:"quote"`. `attribution` у цитаты необязателен, а не придуман.

**Важное ограничение:** в тексте поддерживается только небольшой набор Markdown (жирный, курсив и простые HTTPS-ссылки). Не вкладывай выделения друг в друга, не используй сырые HTML-теги, JavaScript-ссылки, встроенные плееры, таблицы, изображения в теле и произвольный Markdown. Неизвестные элементы отклоняются, HTML-строки выводятся как текст, а не выполняются. Источник по-прежнему отдельно в блоке «Первоисточник».

Оформление является **данными редактора**, а не HTML-кодом, который редактор мог бы выполнить на сайте. Структура сохраняется при `editorial_inbox/stories/<id>.json` → `content/approved/<id>.json` → готовой статье `articles/<id>/index.html`.

Не применять эту конвертацию к постам Threads/X и не переделывать исторический архив: изменения предназначены для новых полных статей, выпущенных сначала на сайте.
