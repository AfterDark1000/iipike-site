# ХПИИ — RSS для будущей трансляции сайта в Дзен

**Адрес:** https://iipike.ru/dzen-rss.xml

Это **отдельная** RSS 2.0-лента с полным текстом `content:encoded`.
Обычный публичный `feed.xml` остается прежним и независимо используется
RSS-читателями. Лента не публикует ничего в Дзен сама по себе: пока пользователь
не подключил адрес через раздел «Свой сайт» Дзен-студии, Дзен её не импортирует.

## Откуда берутся новые материалы

`scripts/publish_approved_article.py` в момент утверждённого выпуска
записывает **в одном Git-коммите** HTML статьи, `news.json`, `feed.xml`,
`sitemap.xml` и `dzen-rss.xml`. Ручного запуска и внешнего cron не нужно.
К моменту успешной выкладки GitHub Pages появятся **и** сайт, **и** RSS-элемент.

Экспортируется только статья, которая:
- уже включена в **публичный** `news.json`, имеет `published_at_utc`, заголовок,
  опубликованный `articles/<id>/index.html` и оригинальный утверждённый
  `content/approved/<id>.json` с `article_markdown`;
- ещё не помечена на сайте `dzen_id` (исторический импорт из Дзена) или
  `site_first_dzen_id` (уже зарегистрированный двойник в Дзене);
- имеет оригинальную локальную обложку WebP, PNG или JPEG.

Отложенные записи из `editorial-intake`, черновики, исторические Дзен-импорты
и неполные материалы **не попадают** в RSS.

**Важное редакционное правило:** HTML внутри `content:encoded` берётся из
**дословного утверждённого Markdown для Дзена**. Ссылки на другие статьи
Дзена не заменяются на сайте-адреса в этом экспорте. На самом iipike.ru
существующая система независимо заменяет их на внутренние ссылки.
Обложка берётся с `iipike.ru`; `guid` — неизменный URL страницы сайта;
`pubDate` — фактическая дата её выпуска в RFC-822.

## До подключения — режим standby

Настройки в `data/dzen_rss_export.json`:

```json
{
  "schema_version": 1,
  "mode": "standby",
  "cutover_at_utc": null,
  "max_items": 40
}
```

В режиме standby RSS **уже наполняется и обновляется автоматически**
по мере выхода новых одобренных публикаций. Но это **только подготовка**.
Само наличие файла, как и его просмотр в браузере, не подключает его к Дзену.

**НЕЛЬЗЯ подключать старую накопленную ленту без согласованного cutover**:
часть материалов уже была вручную опубликована в Дзене, а платформа может
создать дубли.

Когда канал наберёт требуемые 10 живых подписчиков и перед подачей адреса
в Дзен-студии:
1. Выбрать точный момент перехода на RSS **после последней ручной публикации**
   в Дзене. Предстоящие материалы, которые попадут в RSS, больше не переносить
   вручную в Дзен.
2. С согласия редактора изменить `mode` на `active` и
   `cutover_at_utc` на UTC-время (например,
   `2026-11-07T12:00:00Z`). Статьи, опубликованные на сайте до этой
   секунды, будут исключены.
3. Пересобрать RSS командой `python3 scripts/build_dzen_rss.py`, проверить
   `python3 scripts/build_dzen_rss.py --check`, провести техническую
   валидацию и только затем подключить адрес в Дзен-студии.
4. Дзен самостоятельно проверит и примет или отклонит ленту; её структура
   не гарантирует одобрения или конкретного формата публикации в ленте Дзена.
   Правила и лимиты Дзен-студии перед подключением перепроверить.

Обе версии текста остаются подконтрольными редакции, но импорт через RSS
может оформляться платформой иначе, чем вручную подготовленная статья.
После подключения обязательно проверить первый импорт и ссылки.

## Защита и диагностика

- RSS содержит максимум 40 последних отобранных выпусков (настройка до 100),
  при ограничении итогового XML менее 10 МБ.
- Заголовок не длиннее 200 символов, абсолютные ссылки, устойчивый `guid`,
  дата в GMT, полная HTML-версия без потенциально опасных HTML-скриптов.
- HTML строит безопасный Markdown-рендерер; скрипты не исполняются.
- `dzen-rss.xml` обновляется только вместе с настоящим выпуском сайта.
- Если будущих материалов нет, лента остаётся валидной, но может быть пустой
  после установления cutover; это нормально до первого выпуска.
- `python3 scripts/build_dzen_rss.py --check` проверяет, совпадает ли
  существующий XML с текущими исходниками.
- Тесты `python3 -m unittest discover -s tests -p 'test_dzen_rss.py' -v`
  не затрагивают Дзен, сайт или секреты.

При запуске впервые корневая `dzen-rss.xml` может содержать только заголовок
канала; она наполнится при следующей реальной публикации сайта. Это не
препятствует автоматической работе далее.

**Внимание:** исторический сборщик Дзен→соцсети продолжит работать независимо.
Автоматическая RSS-трансляция ещё не включена, не тестировалась на реальном
канале и **не равнозначна подтверждённой возможности создания черновиков
Дзена**.
