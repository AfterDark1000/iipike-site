# Хроники Пикирующего ИИ — сайт

## Действующий выпуск: сначала iipike.ru, затем ручной Дзен

**Рабочий редактор ChatGPT**, а не эксперимент Gemini. После решения человека «берём» редактор отправляет **полный, дословный Markdown** утверждённой статьи в `editorial-intake/editorial_inbox/stories/<id>.json`, Художник из любого доступного чата добавляет настоящий файл обложки в `editorial-intake/editorial_inbox/covers/<id>.*`. GitHub Actions сам проверяет соответствие, собирает HTML и индексы, выполняет регрессионные проверки, безопасно дописывает коммит в `main` и отдельно запрашивает пересборку Pages. **Ручной PR для каждой новости не нужен; Дзен остаётся ручным этапом после успешного развёртывания сайта.** Старый кросспостинг из Дзена не меняется.

Точный рабочий контракт и формат без потери оформления: [editorial_inbox/README.md](editorial_inbox/README.md), [CHATGPT_EDITOR_INSTRUCTIONS.md](editorial_inbox/CHATGPT_EDITOR_INSTRUCTIONS.md), [RICH_TEXT_FORMAT.md](editorial_inbox/RICH_TEXT_FORMAT.md). `--audit` в `scripts/site_first_inbox.py` — безопасный просмотр входящих; команду `--stage --publish` в особых случаях можно использовать вручную на изолированной ветке.

Основной адрес: https://iipike.ru/ (GitHub Pages, репозиторий `AfterDark1000/iipike-site`).

**Очередь комментариев:** [экран комментинга](https://iipike.ru/admin/commenting/) доступен из админки. Сборщик читает открытые ленты изданий и готовит черновики; отправка комментариев только вручную. Прямой сбор публикаций Дзена пока недоступен: при отсутствии подтверждённой ссылки экран предлагает поиск и явно показывает ограничение. Настройка и диагностика: [docs/COMMENTING_QUEUE.md](docs/COMMENTING_QUEUE.md).

Это статический сайт ХПИИ: главная страница со ссылками на опубликованные новости в Дзене, редакционный реестр, лаборатория помеченных **НЕ ОПУБЛИКОВАНО** черновиков и пилотная авторская статья в `articles/google-search-ai-links/`.

**Поисковая индексация:** `sitemap.xml` содержит только реально опубликованные HTML-материалы сайта из `news.json` и главную страницу. Черновики и служебный реестр имеют `noindex, nofollow` и в карту сайта не включаются. RSS `feed.xml` ведёт на `iipike.ru`; GUID существующего пилотного материала оставлен неизменным, чтобы не создавать дубль у подписчиков RSS.

После добавления **редактором проверенной и опубликованной** новой HTML-статьи: добавьте её в `news.json`, укажите `<link rel="canonical" href="https://iipike.ru/articles/<slug>/">` в HTML, затем выполните:

```sh
python3 scripts/build_sitemap.py
python3 -m unittest discover -s tests -p 'test_search_indexing.py' -v
```

Автоматические черновики нельзя записывать в `news.json` или индексировать без редакционной проверки. График Дзен → соцсети не изменён; полноценный автоматический site-first выпуск утверждённых новостей реализован отдельно от экспериментальных черновиков.

Для подключения Яндекс Вебмастера добавьте `https://iipike.ru/`, выберите подтверждение HTML-файлом или метатегом и добавьте выданный сервисом **конкретный** файл/код в этот репозиторий. После подтверждения отправьте `https://iipike.ru/sitemap.xml`. Никаких кодов подтверждения заранее не придумываем.

Первоисточник пилотной статьи: https://blog.google/products-and-platforms/products/search/updates-ai-mode-overviews-explore-web/

## Ручное восстановление/диагностика утверждённой статьи

1. Редактор проверяет факты, первоисточники, текст и обложку, затем кладёт JSON по образцу `content/approved/README.md` в `content/approved/<slug>.json`. Сырые автоподборки из `drafts/` публиковать запрещено.
2. Проверка **без изменения файлов**: `python3 scripts/publish_approved_article.py <slug>`.
3. Явная генерация после утверждения: `python3 scripts/publish_approved_article.py <slug> --publish`.
4. Просмотреть diff: HTML в `articles/<slug>/index.html`, `articles/index.html`, `news.json`, `feed.xml`, `sitemap.xml` и отправить отдельный PR на проверку. Сайт изменится только после слияния в `main` и успешного GitHub Pages деплоя.
5. Проверить: `python3 scripts/build_sitemap.py --check`, `python3 -m unittest discover -s tests -p 'test_search_indexing.py' -v` и `python3 -m unittest discover -s tests -p 'test_approved_publisher.py' -v`.

Команда не трогает кросспостинг, не вызывает внешних API, не публикует в Дзен и отказывает в повторной записи поверх уже опубликованного материала. Авторизация утверждения обеспечивается редакционными правами на GitHub, а не полем JSON как криптографической подписью.

## Рубрики, редакционный архив и перелинковка

У сайта четыре фиксированные рубрики: [Новости ИИ](https://iipike.ru/rubrics/news/), [Скайнет просыпается](https://iipike.ru/rubrics/skynet/), [ИИ, ты чего творишь?](https://iipike.ru/rubrics/what-are-you-doing/), [Громко сказано](https://iipike.ru/rubrics/quotes/). Каждая статья относится к **одной** рубрике, формат/тема дополнительно задаётся в `section`. Пустые рубрики доступны в навигации, но имеют `noindex` и отсутствуют в Sitemap до появления первой публикации.

История из `AfterDark1000/dzen-telegram-crosspost/editorial_full_catalog.json` сохранена как **read-only snapshot** в `data/editorial_full_catalog_snapshot.json` (218 записей на 03.11.2026). Снимок служит для сверки дублей, подбора кандидатов и безопасных переходов на подтверждённые статьи Дзена. Он не считается реестром опубликованных **на сайте** статей; им остаётся `news.json`.

Для обновления рубрик: `python3 scripts/build_rubrics.py`. Для проверки без изменений: `python3 scripts/build_rubrics.py --check`. Скрипт публикации утверждённых статей обновляет рубричные HTML автоматически.

**Перенос десяти статей:** сохраняем **исходные даты публикации каждой статьи в Дзене**. В `published_at_utc` записывается подтверждённое время из исторического каталога, а в `published` — тот же день в `Asia/Yekaterinburg`. На странице видна только **одна** дата: «Опубликовано: <исходная дата>»; отдельная дата переноса на сайт не показывается и не записывается как новая публикация. Ссылка на исходную публикацию в Дзене сохраняется. Для значимых правок существует необязательное `modified_at_utc`: только в скрытых SEO-метаданных (`article:modified_time`, JSON-LD `NewsArticle.dateModified`) и `<lastmod>` в Sitemap. Первоначальную дату публикации не меняем. Отображение поисковой системой остаётся на её усмотрение.

Связи назначает редактор через `related_dzen_ids` (до четырёх); ссылки по неподтверждённым старым URL не создаются. После переноса второго связанного материала при следующем выпуске уже утверждённые HTML обновляются и ссылки переключаются с Дзена на локальную статью. Для выбора кандидатов: `python3 scripts/suggest_related.py <slug>` (только советы, без автоматической вставки). Старый Дзен-конвейер не затронут.

CI проверяет `test_site_rubrics_related.py`, `test_approved_publisher.py`, `test_search_indexing.py` и соответствие статических страниц генератору. **Копии изображений по-прежнему надо предоставлять отдельно**.

## Главная: полные публикации на собственном сайте

Главная страница теперь показывает **настоящие опубликованные материалы** из `news.json` непосредственно в HTML: одну ведущую статью и четыре соседних материала. Так ссылки доступны поисковым роботам без JavaScript; отдельная JS-лента Дзена остаётся для новостей, которых ещё нет на сайте.

Выпуск утверждённой статьи через `scripts/publish_approved_article.py <slug> --publish` одновременно обновляет главную. Дополнительные команды: `python3 scripts/build_home_published.py` (пересборка вручную), `python3 scripts/build_home_published.py --check` (проверка без изменений). В карточках и рубриках читатели видят оригинальные даты Дзена по-русски, а `published_at_utc`, RSS, `NewsArticle.datePublished` и Sitemap сохраняют исходные машинные даты.

## Исторический архив ХПИИ — вторая партия (30 материалов)

Перенесены дополнительные **30** уже опубликованных в Дзене авторских статей: полный текст, утверждённая обложка 16:9, первоначальная дата и адрес исходной публикации. После переноса на собственном сайте находятся **41** HTML-статья, включая пилотную. Эти копии не означают создания «новых» новостей задним числом.

**Ничего из Дзена не удаляем!** Старые публикации, просмотры, комментарии, ссылки и история канала остаются на своих местах. Сайт — независимое постоянное хранилище и первая площадка для *новых* выпусков, Дзен — дополнительная площадка распространения. Подключение автоматического RSS-импорта в Дзен пока заблокировано порогом 10 подписчиков, поэтому работающий маршрут Дзен → соцсети не меняется без отдельной проверки.

Исторические статьи имеют блок «Архивная публикация» со ссылкой на оригинал в Дзене. Где первичный технический документ не был заново подтверждён, ссылка на старую статью обозначена как архивная, а не выдумана ссылка на внешний источник. Полные старые тексты перепубликованы без выдуманных содержательных правок, а дата `modified_at_utc` отсутствует, если редакция не проводила реального обновления.

Для третьей партии сверены **30** подтверждённых заголовков, идентификаторов, ссылок и исходных времён Дзена из исторического каталога. Изображения взяты из ресурсов, принадлежащих этим же публикациям (29 обложек 1672×940/941 и одна 1200×676), без генерации замен.

Один предварительно выбранный материал об американском падении акций Intel и Alphabet **отложен** из-за недоступного изображения по публичному адресу в Дзене. Перепроверка всех исторических фактических утверждений по независимым первоисточникам — отдельная редакционная работа; этот импорт сохраняет оригинальные авторские тексты.

Для импортов без отдельно перепроверенного первоисточника указываем авторскую архивную публикацию в Дзене, не выдумывая ссылки.

Исследовательские workflow, загрузчики и диагностические данные остаются в отдельной непубличной ветке работы и не входят в производственную сборку.

## Автоматизация следующих выпусков (после первого Astra)

Для новых материалов без повторного ручного PR: редактор ChatGPT отправляет **исходный утверждённый Markdown** в `editorial_inbox/stories/<id>.json` (`article_markdown`), Художник — настоящий бинарный файл в `editorial_inbox/covers/<id>.*`, оба — на `editorial-intake`. Workflow проверяет обе части и полный архив, делает безопасное обновление `main` без force-push и инициирует GitHub Pages rebuild. **Это не автоматическая публикация в Дзен.** Редакционные указания: [CHATGPT_EDITOR_INSTRUCTIONS.md](editorial_inbox/CHATGPT_EDITOR_INSTRUCTIONS.md); формат: [RICH_TEXT_FORMAT.md](editorial_inbox/RICH_TEXT_FORMAT.md). Старые инструкции о ручном релизном PR описывают первый пилот Astra.
