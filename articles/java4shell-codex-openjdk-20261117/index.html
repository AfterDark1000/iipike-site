Скайнет просыпается

ИИ за час нашёл дыру в Java, которую пять месяцев не чинили

Codex нашёл уязвимость в обработчике Base64 OpenJDK за час; исследователи Calif показали выполнение чужого кода на тестовых серверах. Об ошибке сообщали ещё в июне, исправления вышли 17 ноября.

Calif — Java4Shell: OpenJDK Base64 vulnerability discovered with Codex ↗

Ошибка в Java оставалась без исправления пять месяцев — а затем через неё исследователи взломали тестовые серверы Jira и Jenkins без пароля.

24 октября специалист компании Calif Quang Luong поручил Codex от OpenAI проверить исходный код OpenJDK. Нейросеть искала уязвимости в самых сложных участках программы.

Через час Codex принёс находку. Ещё два часа ушло на создание первого работающего эксплойта — программы, которая использует уязвимость для взлома.

На токены Codex ушло меньше $200.

Дыра, о которой уже знали

Ещё 9 июня пользователь под ником sundarms сообщил разработчикам Java о регулярных аварийных завершениях программы. В сентябре появился способ воспроизвести ошибку, а другой разработчик даже предложил исправление.

Но предложенную заплатку так и не включили в OpenJDK. Запрос на изменение закрыли.

Команда Calif обнаружила ту же ошибку независимо. Codex при поиске не обращался к старым сообщениям об этой проблеме.

По темеOpenAI покупает Pierre: её инструменты уже работают в CodexНовости ИИ · 6 ноября 2026

Раньше разработчики видели сбой Java. Теперь исследователи показали, как использовать его для взлома.

Как через Java взламывали серверы

Проблему нашли в ускоренном обработчике Base64 — распространённого способа передачи данных в текстовом виде.

Специально сформированные данные заставляли Java записывать информацию за пределами выделенной области памяти. Исследователи использовали эту ошибку, чтобы запускать собственный код внутри чужого приложения.

На тестовых установках Calif продемонстрировала атаки без авторизации на Jira, Jenkins, Confluence, Keycloak и несколько других популярных серверных продуктов.

Уязвимость назвали Java4Shell, ей присвоили номер CVE-2026-114938.

Она затрагивает определённые версии OpenJDK 17, 21, 25 и 27 на процессорах x86-64 с поддержкой инструкций AVX-512 VBMI. Именно в ускоренном коде для этих процессоров и пряталась ошибка.

17 ноября Oracle и OpenJDK выпустили исправления.
