# Утверждённые материалы — ХПИИ

Здесь **только** проверенные редактором материалы, которые разрешено публиковать на сайте. `drafts/`, очередь редактора и лента Дзена **не являются** источником автопубликации.

Для публикации создайте файл `content/approved/<slug>.json` с полями ниже. Имя файла и `slug` должны совпадать. `slug` содержит только маленькие латинские буквы, цифры и дефисы. Картинка должна уже находиться в `assets/` (png/jpeg/webp/svg).

Пример схемы (показанные название и источник — **заглушки, не новость**):

```json
{
  "slug": "example-article",
  "status": "approved",
  "rubric": "news",
  "approved_by": "editor",
  "approved_at": "2026-11-03",
  "title": "Пример заголовка",
  "summary": "Краткое проверенное описание материала",
  "published": "2026-11-03",
  "published_at_utc": "2026-11-03T15:00:00Z",
  "modified_at_utc": "2026-11-03T16:00:00Z",
  "event_date": "2026-11-02",
  "section": "РАЗБОР",
  "source_url": "https://example.org/story",
  "source_title": "Официальный первоисточник",
  "related_dzen_ids": [],
  "cover": "assets/approved-article-cover.webp",
  "paragraphs": [
    {"type": "lead", "text": "Проверенный вступительный абзац."},
    {"type": "p", "text": "Проверенное продолжение текста."},
    {"type": "h2", "text": "Подзаголовок"},
    {"type": "p", "text": "Ещё один проверенный абзац."}
  ]
}
```

Команда `python3 scripts/publish_approved_article.py <slug>` только проверяет подготовку, ничего не изменяя. Для генерации нужно отдельно указать `--publish`.

**Важно:** поле `status=approved` само по себе не является гарантией корректности. Утверждение должно соответствовать реальному редакционному решению; при публикации через GitHub требуется просмотр diff и PR. Скрипт не запускается по расписанию, не вызывает внешние API и ничего не отправляет в Дзен или соцсети.

## Категории, дата публикации и скрытая дата правки

Рубрика обязательна, выбирается **одна**: `news` («Новости ИИ»), `skynet` («Скайнет просыпается»), `what-are-you-doing` («ИИ, ты чего творишь?»), `quotes` («Громко сказано»). Формат/подтема остаётся в `section`.

**При переносе статьи из Дзена публикуем на сайте с первоначальной датой редакционной публикации, совпадающей с историей Дзена**, а не с датой технической загрузки на GitHub Pages. На фронтенде одна дата: **«Опубликовано: <дата Дзена>»**.

- `published_at_utc` — реальный исходный момент публикации в Дзене (UTC, `Z`) **строго совпадает с подтверждённым `published_at_utc` в редакционном архиве**. Значение нельзя подменять предполагаемой датой и нельзя брать из истории ID.
- `published` — дата этого момента в редакционном часовом поясе **Asia/Yekaterinburg (UTC+05)**. Это основной день публикации в HTML, каталогах и рубриках.
- `dzen_id` и `dzen_url` — ID и ссылка на ту же подтверждённую публикацию; ссылка «Версия в Дзене» остаётся, но без отдельной даты.
- `event_date` — дата самого события, не смешивается с датой публикации.
- `modified_at_utc` — **необязательный** момент последней *существенной* редакционной правки, не раньше исходной публикации и не в будущем. Его выставляет редактор только после реальной правки. Отображение на странице не меняется; при наличии значения появляются `article:modified_time`, `NewsArticle.dateModified` и `<lastmod>` в Sitemap.
- `original_dzen_published_at_utc` **не использовать**: эта дата дублировала исходную и больше не допускается.

Для новых статей, первоначально опубликованных на `iipike.ru`, поле `published_at_utc` означает их первый реальный выпуск. Не ставим задним числом фиктивные даты и не создаём искусственные «обновления» ради поисковика. Формат PDF/картинки/тексты — без изменений.

**Примечание по SEO:** наличие старой даты в HTML не гарантирует, что Яндекс или Google выберут её в поисковой выдаче. Google рекомендует отражать существенное обновление и для читателя; по запросу редакции пока показываем только исходную дату, а дату правки скрываем в метаданных.

### Перелинковка без выдуманных ссылок

`related_dzen_ids` — до четырёх **вручную отобранных** идентификаторов тематически связанных статей. В `data/editorial_full_catalog_snapshot.json` находится копия исторического каталога редактора (218 записей на 03.11.2026). Она **только для чтения** и не подменяет самостоятельный список статей сайта `news.json`.

Автоматические ссылки разрешены лишь для записей, у которых название и адрес действительно зафиксированы публичной лентой Дзена; 40 старых восстановленных по логам и 15 без названий требуют отдельной проверки. «Дневник канала» исключён. Если связанный материал уже перенесён на сайт, ссылка будет внутренней, иначе — на проверенный адрес в Дзене.

Подсказки кандидатов (без публикации): `python3 scripts/suggest_related.py <slug>`. Совпадение слов ещё не означает смысловую связь, поэтому окончательный выбор — за редактором.

После подготовки источника: `python3 scripts/publish_approved_article.py <slug>` (только проверка), затем по отдельному редакционному решению `python3 scripts/publish_approved_article.py <slug> --publish` в рабочей ветке, просмотр diff, тесты и pull request.

Обложку нужно предварительно положить в `assets/` — механизм не пытается загружать картинку с Дзена и не создаёт её автоматически.
