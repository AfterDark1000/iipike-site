# ХПИИ — накопители небольших экспериментов

## Зачем

Сортировщик сохраняет любопытные пользовательские ИИ-проекты, которым
недостаточно содержания для собственной статьи, и объединяет их в тематические
накопители. Когда вместе они складываются в **самостоятельный интересный материал**,
главред открывает подборку редактору. Число участников не задано: 3–6 —
обычный ориентир, не квота и не повод добавлять слабую историю.

**Крупный, эффектный, проверенный эксперимент** сразу получает обычный
`hot` / `full`, даже если рядом есть похожий накопитель. Мелкий и
неинтересный даже для подборки — кандидат на отклонение. Нельзя автоматически
переводить все пользовательские проекты в подборки.

## Текущие данные и блокировка

- `data/site_news_pool.json` сохраняет старые неизменяемые `sequence/pool_id`
  и `queued/in_review/approved/rejected`. Новый статус здесь **не вводится**.
- `data/editorial_collections.json` — отдельный реестр тем, этапов и членов.
  Содержит `collecting` и `ready_for_editor`, пояснение и точные пары
  `sequence/pool_id`.
- `data/editorial_routing.json` обеспечивает **реальную техническую блокировку**.
  Для `collecting`: ведущий `defer/hold`, остальные `linked_secondary/hold`.
  Для `ready_for_editor`: ведущий `linked_primary/long`, остальные по-прежнему
  `linked_secondary/hold`. Автономный редактор не забирает связанные группы.
- `scripts/editorial_collections.py --check` проверяет, что обе структуры
  полностью совпадают и не ссылаются на изменённые ID или уже занятую
  новость внутри `collecting`.

Никакой ведущий материал из `collecting` не должен попадать ни в ручной,
ни в автономный, ни в короткий редактор до явного решения главреда.
**Набранная четвёрка сама по себе не означает готовность.**

## Обязательная ежедневная работа сортировщика

1. Прочитать все `queued`, действующую маршрутизацию и накопители, сверить
   архив сайта, опубликованные и ожидающие материалы и «Новости коротко».
2. Оценить каждое подходящее событие: самостоятельная сенсация (полная),
   конкретная маленькая история (накопитель) или пустяк (отклонение).
3. Предложить пополнение существующей **смысловой** темы либо новую группу.
   Не собирать просто «всё про Claude»; подборке нужен общий сюжет и несколько
   отличающихся опытов.
4. Проверить первоисточники, уникальность и полноценность демонстраций.
   Выявить уже опубликованные элементы. Подозрительное демо оставлять с
   явной оговоркой в `note`, не представлять непроверенное достижение как факт.
5. Если группа дозрела по качеству, предложить `ready_for_editor`.
   До явного согласия главреда **не открывать редакторскую очередь**.
6. На следующем разборе возвращаться к `collecting`, не теряя их из-за давности
   и не плодя параллельные подборки на ту же тему.

Разрешено пополнять накопитель любым числом элементов в пределах 1–30;
для первого кандидата даже одиночный элемент допустим, но редактору его
не открывать как готовую подборку без самостоятельной смысловой ценности.

## Как записывать решения (только после прямого одобрения главреда)

Используется тот же **неизменяемый request + SHA-bound receipt** в
`data/editorial_triage/requests/<unique>.json` и
`data/editorial_triage/receipts/<same>.json`. Штатный
`.github/workflows/hpii-triage-requests.yml` применяет одним коммитом
**реестр, маршруты, пул и квитанцию**. Никаких правок реестров в обход
обработчика, самостоятельной публикации и автоутверждения текста.

### Создать, пополнить, переименовать или открыть накопитель

Один запрос `collection_upsert` передаёт **полный итоговый состав**.
Чтобы пополнить, перечислить прежних участников и новые. Для открытия
заменить `state` на `ready_for_editor`, только после утверждения главредом.

```json
{
  "schema_version": 1,
  "action": "collection_upsert",
  "worker": "hpii-morning-triage",
  "approval": "explicit_chief_editor_chat_command",
  "collection": {
    "group": "ai_local_gadgets_20261125",
    "title": "Небольшие ИИ-эксперименты на слабых устройствах",
    "state": "collecting",
    "primary_sequence": 100,
    "members": [
      {"sequence":100, "pool_id":"n-0123456789abcdef"},
      {"sequence":109, "pool_id":"n-fedcba9876543210"}
    ],
    "note": "Иллюстративные ID: сверить точные исходники и смысловые пересечения."
  }
}
```

Значения в примере **не реальные**. Отбирать ID и номера из свежего
`main/data/site_news_pool.json`. `members` строго по возрастанию `sequence`.
Ведущий номер принадлежит группе и может быть любым из участников.

В группе с состоянием `ready_for_editor` нельзя добавлять новые истории;
сначала нужно отдельно согласовать изменение и проверить, не занят ли материал.
Переключение состояния допускается лишь для ещё свободных `queued`.
Условная готовность без полноценной проверки — основание остаться в `collecting`.

### Вывести внезапно ставший большим эксперимент из накопителя

После одобрения главредом `collection_release_member` переводит *не ведущий*
сюжет в самостоятельный `full` или `hot`:

```json
{
  "schema_version": 1,
  "action": "collection_release_member",
  "worker": "hpii-morning-triage",
  "approval": "explicit_chief_editor_chat_command",
  "group": "ai_local_gadgets_20261125",
  "member": {"sequence":109, "pool_id":"n-fedcba9876543210"},
  "decision": "hot"
}
```

Вывод ведущего требует отдельного решения с выбором новой ведущей истории;
обработчик намеренно **отказывает**, чтобы не потерять всю группу.

## Безопасность

- Только явное утверждение главреда разрешает новую заявку.
- Нельзя включать уже `in_review/approved/rejected` в новую группу,
  менять их маршруты или тихо исключать существующих членов.
- Нельзя забирать `hot` в накопитель под предлогом будущего выпуска.
- Обычные триаж-заявки не должны менять зарегистрированную группу, нарушая
  этап накопления: обработчик выдаст `rejected`.
- До квитанции `status=applied` и проверки `data/editorial_routing.json`
  не объявлять новую группу накопленной или открытой.
- Группы из прежнего формата `linked_primary/linked_secondary` не считаются
  накопителями, пока они не внесены в отдельный реестр.
- Открытие `ready_for_editor` **не означает** публикацию, утверждение статьи,
  заказ обложки или запуск внеочередного слота.
