# ХПИИ — Автономный художник: инструкции для существующей задачи

**Исполнитель:** существующая задача ChatGPT «ХПИИ — Автономный художник» (ID `6afc408992f08191810f60872d211636`). Не новый FLUX-генератор, не новый плагин, не новый слот задачи. Расписание/включённость регулируются отдельно и **не изменяются** этим документом.

Прочитать [полное зеркало художественных инструкций плагина](artist_plugin/README.md), включая **весь** [главный навык](artist_plugin/skills/hpii-cover/SKILL.md), [визуальный стандарт](artist_plugin/skills/hpii-cover/references/HPII_Cover_Standard.md), [приёмы](artist_plugin/skills/hpii-cover/references/artistic-toolkit.md), [композиции](artist_plugin/skills/hpii-cover/references/composition-toolkit.md), [антиповторы](artist_plugin/skills/hpii-cover/references/style-diversity-regression.md) и [навык автодрафтов](artist_plugin/skills/hpii-auto-cover/SKILL.md). [Сценарии проверки арт-дирекции](artist_plugin/skills/hpii-cover/references/art-direction-tests.md) и [производственные проверки](artist_plugin/skills/hpii-cover/references/production-regression-checks.md) использовать как проверочный материал; не путать тестовые примеры с готовой композицией.

## Один безопасный проход

1. Прочитать актуальные `editorial_inbox/auto_drafts/*.json`, `auto_decisions/*.json`, `auto_covers/`, `auto_cover_decisions/`, `auto_handoffs/` в ветке `editorial-intake`.
2. **Сначала возвраты с замечаниями:** найти `cover_revision_requested` по версии `vN`, сопоставить файл решения с SHA изображения и метаданных и с неизменённой утверждённой ревизией текста. Подготовить исключительно следующую `vN+1` (максимум `v5`) с дословным учётом замечаний. Если таких нет — взять наиболее ранний свободный одобренный текст и подготовить `v1`.
3. Если в следующей версии уже есть кандидат, если текст изменился, если есть handoff либо не совпадают утверждённые SHA — **не генерировать дубль**, не перезаписывать файлы и не менять текст.
4. Полноценно подготовить художественную концепцию **по зеркалу стандарта**, не просто по одному `cover_brief`. Результат — авторская 16:9-обложка, короткий корректный русский заголовок, проверка смысла и антиповторов. Никаких FLUX, экспериментального Gemini-контурa или замены изображения шаблонной цветной типографикой.
5. Важно: задача может не иметь выбранной в ручном Work-чате модели Sol 6.2. **Не утверждать, что работала на Sol 6.2, если это не подтверждено текущей средой.** GitHub-инструкция не способна переключить модель выполнения. Использовать только реально доступный штатный генератор ChatGPT Images; при его отсутствии — безопасно остановиться с понятной причиной.
6. **Обязательно выполнить [технический маршрут бинарной передачи](AUTO_COVER_BINARY_BRIDGE.md), а не останавливаться на словах «GitHub не принимает локальный файл».** Проверенный способ: реальный WebP → ASCII Base64 → `mcp__GitHub__create_blob` с `encoding="base64"` → проверка Git blob SHA → атомарный `create_tree`/`create_commit`/`update_ref` → повторное чтение. Для получения Base64 из отдельной среды доступен `scripts/prepare_auto_cover_transfer.py` и временный текстовый экспорт через Files. Только после получения и проверки фактических байтов сохранить новую версию `editorial_inbox/auto_covers/<id>-r<text_revision>-v<version>.webp` и одноимённую `.json` в `editorial-intake`, сверив SHA черновика, утверждения и файла до и после записи. **Если нет доступа к исходному изображению или Files-транспорту, честно остановиться и предложить ручную загрузку в админке.** Не подменять невозможную передачу бинарного файла ссылкой на изображение в чате.
7. Кандидат ждёт отдельного решения владельца в `/admin/auto-editor/`; автономная задача **не ставит approve_cover**, не формирует `editorial_inbox/stories/`, не передаёт в боевую очередь и не публикует статью, Дзен, соцсети.
8. За один проход — максимум один осмысленный кандидат. Если новых работ нет — без повторных сообщений. При ошибке доступа не обещать фонового продолжения и не имитировать успешный результат.
