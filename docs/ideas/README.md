# ХПИИ — копилка идей

Здесь храним задумки для проекта «Хроники Пикирующего ИИ», которые сейчас не планируем реализовывать, но хотим сохранить. Это **не очередь задач и не план работ**: запись идеи не запускает разработку, закупки, производство или публикацию.

## Как пользоваться

- Новые идеи добавляем в этот файл отдельными карточками с очередным ID, датой, направлением и кратким описанием. Можно записать сырую мысль — детали уточним позже.
- Статусы: **отложено** (сохранена на будущее), **обсуждаем** (оцениваем возможность), **в работе** (отдельно принято решение начать), **реализовано**, **отказались**.
- Не удаляем реализованные или отклонённые идеи: меняем статус, чтобы сохранялась история.
- По запросам «запиши идею», «покажи копилку идей», «вернёмся к идее №…» используем этот файл. Здесь не размещаем новости, черновики статей и текущие технические инциденты.

## IDEA-002 — ВКонтакте: карточка ссылки плюс отдельный живой текст

- **Дата:** 15 ноября 2026
- **Направление:** ВКонтакте / оформление кросспостинга
- **Статус:** отложено
- **Суть:** вместо обычной публикации с прикреплённой обложкой рассмотреть формат, как у Т—Ж: ВК формирует **карточку ссылки на статью сайта** (обложка, заголовок, адрес), а над или под ней размещается **уникальный короткий сопроводительный текст**, написанный специально для ВК — разговорный, цепляющий, допустим уместный юмор, без механического дублирования статьи.
- **Что уже есть:** на сайте ХПИИ настроены метаданные `og:image` и заголовки; редактор уже готовит отдельные поля `vk_title` и `vk_summary`. Текущий `vk-rss.xml` передаёт отдельную JPEG-обложку и анонс, но это не обязательно даёт нужную карточку.
- **Что проверить при возвращении:** может ли действующий RSS-импорт ВК стабильно показывать **именно предпросмотр ссылки** вместе с самостоятельным текстом; как избежать повторной картинки; если RSS не позволяет — рассмотреть другой способ кросспостинга. Сравнить результат и вовлечённость с нынешними постами на нескольких примерах.
- **Решение сейчас:** только записать идею. Не менять RSS, редакторские инструкции, публикации, кросспостинг или уже вышедшие записи.

## IDEA-004 — Единая авторизация и более долгая сессия в админке

- **Дата:** 20 ноября 2026
- **Направление:** Админка / удобство и авторизация
- **Статус:** реализовано (23 ноября 2026; GitHub OAuth остаётся обязательным при первом входе)
- **Суть:** авторизоваться в админке ХПИИ **один раз**, после чего переходить между её вкладками и разделами без повторного входа; не терять сессию при открытии новой вкладки или перезапуске браузера.
- **Реализация:** единый клиент `admin/auth/hpii-auth-client.js` сохраняет подписанный токен админки в хранилище сайта `iipike.ru`, совместно используемом всеми вкладками этого браузера. Прежний временный `sessionStorage`-токен переносится при первом входе, если ещё действителен. Период действия нового токена — **7 суток** от входа, без бессрочного или скрытого продления. Сервер Cloudflare Worker проверяет подпись, срок и точный GitHub ID владельца для каждого защищённого запроса. OAuth-ключи GitHub и секреты репозитория остаются только на сервере.
- **Выход:** кнопка «Выйти из админки» на каждой странице убирает токен из хранилищ текущего браузера; остальные открытые вкладки получают сообщение через `storage` и закрывают экран админки. При отказе сервера `401` также требуется новый вход. Проблема сети `503` сама по себе сессию не удаляет.
- **Безопасность и ограничение:** подписанный токен хранится в доступном JavaScript хранилище сайта; не использовать устройство совместно без явного выхода. Выход очищает доступ в данном браузере, но не отзывает уже скопированный подписанный токен на сервере. Срок сессии фиксирован семью днями. Для удалённого отзыва токенов потребуется отдельное серверное хранилище/механизм revocation; не выдавать браузерный выход за серверный отзыв. Изменение не создаёт новые права и не отключает OAuth.
- **Проверка:** переход между `/admin/`, `/admin/pool/`, `/admin/auto-editor/`, `/admin/first-car/`, выход и синхронизация вкладок; отдельные серверные тесты подписи и TTL.

## IDEA-005 — Корректор-стилист для текстов ХПИИ

- **Дата:** 20 ноября 2026
- **Направление:** Редакционный конвейер / качество текстов
- **Статус:** отложено
- **Суть:** рассмотреть отдельного агента — **корректора-стилиста (литературного редактора)**, который получает уже подготовленную и проверенную редактором статью и доводит её до нужного звучания ХПИИ. При необходимости не только исправляет шероховатости, но и существенно переписывает подачу: убирает сухость, нейросетевые обороты, повторы, улучшает начало, ритм и композицию, делает текст живым и цепляющим.
- **Разделение ролей:** редактор отвечает за факты, источники, смысл и исходную статью; стилист — за литературную форму; главред принимает окончательный вариант. Стилист не подменяет фактчекинг и не утверждает материалы самостоятельно.
- **Ограничения:** не менять смысл новости, не преувеличивать цифры, не добавлять выдуманные сцены, цитаты, эмоции и неподтверждённые факты. Не применять одну и ту же интонацию ко всем рубрикам и событиям.
- **Что продумать при возвращении:** сначала разработать и согласовать сам литературный стиль ХПИИ и критерии качественной правки; затем протестировать стилиста на трёх готовых статьях разных типов, сравнить с исходниками и только после этого решать, стоит ли встраивать его отдельным этапом между редактором и главредом.
- **Решение сейчас:** сохранить задумку. Нового агента не создавать, рабочий конвейер не менять.

## IDEA-006 — Подборка и применение Agent Skills для ХПИИ и клуба авторов

- **Дата:** 26 ноября 2026
- **Направление:** ИИ-агенты / автоматизация редакции / клуб авторов

- **Возможные направления для ХПИИ:** работа с GitHub и файлами проекта, проверка источников, редакторские и корректорские процедуры, подготовка публикаций и другие повторяющиеся операции. Отдельно оценить, где выгоднее взять готовый навык, а где написать собственный под наши правила.
- **Возможные направления для клуба авторов:** помощь с подготовкой и проверкой публикаций, разбор материалов и другие полезные автору действия. Не превращать каталог в набор случайных установок ради количества.
- **Что проверить при возвращении:** качество и актуальность навыков; автора и исходный репозиторий; содержимое `SKILL.md`; наличие скриптов, команд и внешних загрузок; требуемые разрешения и потенциальные риски. Проверять навыки в изолированной среде, начинать с небольшого набора и сравнивать результат с текущим процессом. Не устанавливать непроверенные навыки глобально и не давать им доступ к секретам и рабочим данным без необходимости.
- **Решение сейчас:** только сохранить направление для отдельного разбора техническим штабом. Ничего не устанавливать и не менять в действующих агентах, редакционном конвейере или клубе авторов.

## IDEA-007 — Изучить «Дзен Текст» и адаптировать локальные проверки для ХПИИ

- **Суть:** изучить реализацию редакторских проверок и выбрать те алгоритмы, которые можно независимо адаптировать для предварительной проверки статей ХПИИ. - **Возможное применение в клубе авторов:** оценить, пригодятся ли такие проверки как отдельный бесплатный инструмент для авторов — например, при подготовке текста перед публикацией.
- **Что проверить при возвращении:** точность алгоритмов на реальных русскоязычных статьях; ложные срабатывания; работу с Markdown и длинными материалами; ограничения поиска по буквальным совпадениям; качество словаря синонимов и сохранение словоформ. Отдельно изучить структуру проекта и условия MIT-лицензии, если решим заимствовать или адаптировать код. Не переносить проверки автоматически без тестирования на материалах ХПИИ.
- **Решение сейчас:** только сохранить проект для технического и редакторского разбора. Не менять конвейер, не запускать разработку отдельного приложения и не обещать интеграцию в клуб.
