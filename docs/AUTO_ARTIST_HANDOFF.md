# ХПИИ — передача готовых автодрафтов нашему художнику

**Актуальный параллельный режим (24.11.2026, решение главреда).** Художник работает независимо от утверждения текста. Выбирать актуальный полноценный `ready_for_review` автодрафт, если по этой ревизии решения нет или есть точное `approve_text`. Не брать отклонённую, возвращённую на доработку, заблокированную или уже переданную ревизию. Сначала замечания к обложкам, затем очередь свободных готовых текстов по `pool_sequence`. Кандидат строго привязан к `article_id`, ревизии, `updated_at` и SHA исходного автодрафта. В существующей схеме v1 поле `source_decision_blob_sha` равно точному SHA действующего approve_text, если он существует на момент регистрации; если решения нет — явно `null`. Никогда не выдумывать SHA. При одобрении обложки до текста `source_text_decision_blob_sha` в человеческом решении может быть `null`; два настоящих утверждения для одной актуальной ревизии всё равно обязательны для handoff. Смена текста аннулирует пригодность старой обложки для текущей ревизии: художник сравнивает сюжет, бриф и изображение, при соответствии может повторно использовать проверенные реальные байты старого WebP как новый кандидат rN-v1 с новыми метаданными, не перенося старое одобрение. Если смысл изменился — новое изображение. Не перерисовывать автоматически и не перепривязывать молча. Сверять SHA и отсутствие запрещающего решения до и после сохранения. Пять кандидатов/генераций в 24 часа, максимум один кандидат за проход; считать все записи и уже сделанные попытки консервативно. Эти правила выбора имеют приоритет над историческим требованием approve_text до начала рисунка в плагинном зеркале. Художественный стандарт, бинарный мост, запрет утверждения и публикации не меняются.

**Разделение:** основной интерактивный художник — чат ChatGPT (в Work пользователь может выбирать Sol 6.2), подключающий плагин `ХПИИ — Художник` / `hpii-artist`. **Автономная задача — отдельный запуск ChatGPT**, который не обязан иметь тот же плагин или модель. Для неё полный художественный стандарт без потерь скопирован в [docs/artist_plugin/README.md](artist_plugin/README.md) и задан входной файл [docs/ARTIST_AUTONOMOUS_AGENT.md](ARTIST_AUTONOMOUS_AGENT.md). Оба используют один художественный стандарт; никакого FLUX для основной редакционной очереди. GitHub-документы не выбирают модель выполнения.

## Откуда получать художественное задание

Источник истины — ветка `editorial-intake` репозитория `AfterDark1000/iipike-site`:

- `editorial_inbox/auto_drafts/<article_id>.json` — текст, `cover_brief`, `article_id`, `revision`, `updated_at` и источники;
- `editorial_inbox/auto_decisions/<article_id>-r<revision>.json` — отдельное подтверждение текста главредом;
- `editorial_inbox/auto_covers/<article_id>-r<revision>-v<version>.webp` — **неутверждённый** кандидат обложки;
- `editorial_inbox/auto_covers/<article_id>-r<revision>-v<version>.json` — статус `ready_for_cover_review`, SHA исходников/картинки и размеры;
- `editorial_inbox/auto_cover_decisions/` — отдельное решение главреда по обложке.

Кандидат доступен по параллельному режиму выше. При наличии готового кандидата без решения не создавать дубль. Если последняя версия получила `revise_cover`, `cover_revision_requested`, выполнить следующую vN+1 (до v5) с точным учётом замечаний; старые файлы не менять. Не брать материалы, уже переданные в `auto_handoffs`.

**Возвраты с замечаниями — раньше новых заявок.** При выборе следующей сперва найти последнюю отклонённую версию и подготовить ровно следующую версию на основе указаний главреда. Среди остальных брать первое подходящее по `pool_sequence`, затем `article_id`. Не подменять этот порядок новым поиском новостей.

## Действия существующего художника

1. Прочитай свою **встроенную** инструкцию `skills/hpii-cover/SKILL.md` вместе с визуальным стандартом. Затем прочитай весь актуальный готовый автодрафт, `cover_brief` и первоисточники. Не делай обложку по одному названию ID. Сравни с последними реально доступными обложками; не заявляй о сравнении недоступных.
2. Создай **одну** авторскую художественную горизонтальную обложку 16:9 через штатный генератор изображений ChatGPT, а не FLUX. Грамотный русский заголовок, художественное разнообразие и отсутствие псевдотекста обязательны. Просмотри фактический результат и проверь соответствие новости.
3. Преобразуй реальные байты изображения в WebP, желательно 1600×900, до 800 КБ, подтверди декодируемый WebP и 16:9. **Используй пошаговый [бинарный мост](AUTO_COVER_BINARY_BRIDGE.md): локальное изображение → проверенный Base64 → GitHub `create_blob(encoding="base64")` → проверка SHA → атомарный коммит.** Это уже проверено на предыдущем кандидате. Если из конкретной среды не удаётся получить байты или передать ASCII Base64, честно сообщи о блокировке, не выдавай это за готовую обложку, не создавай JSON `ready_for_cover_review` и не рисуй повторно каждый час один и тот же сюжет.
4. Сохрани в `editorial-intake/editorial_inbox/auto_covers/<article_id>-r<revision>-v<version>.webp` (v1 для первого рисунка, v2 после отклонения v1, и т. д.) **и только потом** метаданные соответствующей версии. Точная схема JSON и проверка SHA изложены в `docs/AUTO_COVER_ARTIST_PILOT.md`; независимая проверка: `scripts/check_auto_cover_pilot.py`. Никакой записи прямо в `editorial_inbox/covers/` без отдельного решения главреда.
5. Перечитай оба сохранённых файла и покажи результат в `https://iipike.ru/admin/auto-editor/` для двух решений: «Утвердить обложку» / «Переделать». До подтверждения **не писать** боевую статью, обложку, Threads, X, Дзен и не запускать публикацию.

## Автоматизация и ограничение вызова

GitHub может **подготовить/выявить** готовую задачу по готовому тексту и проверить сохранённый результат, но **не умеет сам вызвать личный ChatGPT-плагин `ХПИИ — Художник`**. Наличие инструкции, cron или workflow **не означает**, что настоящий художник получил задание и начал рисовать. Не заменять его вызовом FLUX. Вызов художника должен быть явно подтверждён в поддерживаемом ChatGPT-процессе (например, сообщением в чате этого плагина) либо через отдельную проверенную интеграцию с исполнителем. Существующая почасовая задача «ХПИИ — Автономный художник» включена; использует полный стандарт из docs/ARTIST_AUTONOMOUS_AGENT.md. На 18 ноября она независимо прочитала очередь, однако пока не доказано, что штатный плановый запуск сам генерирует изображение: v2 ранее изготовлена в техштабе через ручной inline-прогон и уже сохранена. Не создавать v2 повторно.

**Безопасная команда в существующем чате плагина:**

> Возьми следующий готовый автодрафт ХПИИ для обложки. Прочитай `docs/AUTO_ARTIST_HANDOFF.md` в `AfterDark1000/iipike-site`, выбери работу по этому регламенту и действуй как наш собственный «ХПИИ — Художник». Никакого FLUX, экспериментального раздела или прямой публикации; только кандидат WebP в `auto_covers` и последующее решение в админке.
