# ХПИИ — решения главреда по автодрафтам

## Безопасный маршрут

Страница `/admin/auto-editor/` читает только материалы ветки `editorial-intake`. При выборе «Утвердить текст», «На доработку» или «Отклонить» открывается предзаполненная заявка GitHub Issue. Главред должен быть авторизован в GitHub и подтвердить её через **Submit new issue**.

Workflow `.github/workflows/hpii-auto-editor-review.yml` срабатывает только на новую заявку, созданную владельцем репозитория, сверяет `article_id`, `revision`, `updated_at`, статус `ready_for_review` и отсутствие предыдущего решения для этой версии. При успехе пишет один JSON в `editorial-intake/editorial_inbox/auto_decisions/<article_id>-r<revision>.json` и оставляет подтверждение комментарием в Issue.

**Ни один путь не меняет статус публикации, не создаёт боевую статью или обложку, не трогает пул, социальные очереди и планировщик.** Одобрение текста имеет статус `text_approved_cover_pending`, а не `editor_approved`.

## Следующий проход автономного редактора

Перед захватом новой обычной новости редактор обязан прочитать `editorial_inbox/auto_decisions/` и `editorial_inbox/auto_drafts/` в ветке `editorial-intake`.

1. Для `feedback_pending_revision` открыть точный автодрафт и заметку главреда, сверить версии и первоисточники. Подготовить исправленную версию **того же** `article_id` с `revision + 1` и новым `updated_at`. Не изменять решения предыдущей версии.
2. Для `text_approved_cover_pending` не брать материал заново, не публиковать и не изменять утверждённый текст без нового согласия; следующий этап — обложка и отдельное разрешение на передачу.
3. Для `rejected` не перерабатывать без отдельного разрешения главреда.
4. Если по текущему `revision` уже есть решение, не показывать кнопки повторного утверждения и не создавать дубликат.
5. Если сохранение новой версии не удалось, оставить существующие файлы без изменений и сообщить о сбое.

**Ограничение:** запись `feedback_pending_revision` сама по себе не запускает ChatGPT-автозадачу и не гарантирует переработку. Исполнитель автономной задачи должен применять этот протокол при следующем запуске; требуется отдельная проверка фактической работы на реальном замечании.

## Контроль

После отправки решения открыть созданный Issue: успешный workflow оставит комментарий с путём файла. Затем обновить страницу панели: она прочитает подтверждённое решение из GitHub. Если workflow упал, решение не считается принятым; нельзя имитировать успех локальной кнопкой.
