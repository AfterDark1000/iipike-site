# Дзен. Локальная проверка A.2

**Пакет опубликован для однократного запуска на Windows. Результат живой проверки на пользовательском компьютере ожидается.** Ручное открытие одной статьи в A.1 и первые HTTPS-ответы остаются отдельными наблюдениями. [Задание A.2](https://github.com/AfterDark1000/iipike-site/pull/216#issuecomment-6984549625) · [Отчёт A/A.1](DZEN_DISCOVERY_STAGE_A.md)

## Запуск

1. Скачайте [Dzen-A2-Windows.zip](https://github.com/AfterDark1000/iipike-site/raw/refs/heads/codex/dzen-stage-a-215/lab/dzen-stage-a2/Dzen-A2-Windows.zip) и распакуйте весь архив в свою папку.
2. Если Python отсутствует, один раз установите Python 3.11 или новее. В установщике оставьте Tcl/Tk и включите добавление Python в PATH. Нужен уже установленный Chrome или Microsoft Edge. [Python для Windows](https://www.python.org/downloads/windows/)
3. Откройте `Start-Dzen-A2.cmd` и нажмите **Проверить доступность**. При первом запуске установится Playwright в папку пакета. Дождитесь завершения. Ввод в браузере для теста не нужен.
4. Отправьте только `dzen-a2-report.json`, который появится рядом с `Start-Dzen-A2.cmd`.

Ссылки под кнопкой можно при желании открыть вручную. Выбранная отметка записывает наблюдение владельца в `ordinary_browser`. Поля, которые программа в таком браузере не измеряет, остаются пустыми. Ручное сравнение можно пропустить и сразу отправить отчёт.

## Что проверяет пакет

- `ordinary_browser` содержит необязательную ручную отметку. `controlled_browser` отражает попытку в установленном Chrome или Edge с JavaScript и временным контекстом. `automated_extraction` содержит поля отрисованной статьи и источники полей.
- Перед запуском проверяются актуальный `robots.txt` и отпечаток изученной редакции условий Дзена. Для ресурсов браузера применяются правила каждого участвующего хоста из ограниченного списка. Playwright проверяет запросы, получает разрешённые ответы и передаёт документ и ресурсы Chromium. Вложенные документы, фоновые каналы, неизвестные хосты и методы записи исключены из пробы. Измерение относится к этому контролируемому режиму.
- Каждый HTTP-редирект проверяется до следующего обращения. Допустимый переход сохраняет идентификатор контрольной статьи. Запрещённый `/push`, путь входа или недоступные правила останавливают этот сценарий. При видимом запросе входа, CAPTCHA и ответе документа 401, 403 или 429 прогон завершается. В отчёте сохраняются только публичные поля, разрешённые адреса статей без параметров и статусы. Тексты и имена комментаторов, профиль, cookies и токены не включаются.
- Статья засчитывается после появления заголовка, текста и метаданных того же адреса. Точная дата извлекается из явной метки публикации. Относительная дата остаётся отдельным полем. Числовые показатели заполняются при однозначном обозначении в интерфейсе. `null` означает отсутствие подтверждения. Одного положительного счётчика комментариев достаточно для наблюдения на конкретной статье. История нужна для оценки канала.

## Состояние проверки

На имитации первого ответа HTTP 302 диагностика проверила правила SSO и остановилась до запроса `/push`. Локальная проверка Chromium с JavaScript на тестовой странице дошла до разрешённого редиректа и выявила конфликт с промежуточной страницей ошибки Chromium. Исправление включено в пакет. Среда разработки отключилась до завершения повторного прогона после исправления. Встроенный разбор DOM прошёл пять проверок на тестовых данных. При сборке проверены структура ZIP, контрольные суммы и содержимое всех пяти файлов. **Нужен отчёт с Windows, прежде чем делать вывод о доступе к Дзене и извлечении полей.**

Если реальный отчёт подтвердит доступ, точные даты и признаки обсуждений, дополнительное измерение A.2 охватит 5–10 материалов одного активного канала. До этого пакет ограничен тремя статьями. Если локальный результат отрицательный, публичный каталог остаётся источником кандидатов по сводным охватам, а карта Дзена — источником прямых адресов. Эти источники пока не закрывают дату публикации и обсуждение конкретной статьи. Этап B не начат.
