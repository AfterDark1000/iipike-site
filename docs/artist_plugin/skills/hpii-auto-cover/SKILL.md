# ХПИИ — Художник: обложка для утверждённого автодрафта

Это **дополнительный режим существующего личного плагина** `ХПИИ — Художник`, не новый генератор. Художественные правила, антиповторы, композиция и контроль качества полностью остаются в `skills/hpii-cover/SKILL.md` со всеми его справочниками.

## Когда выполнять

Только по явной команде пользователя взять следующую обложку автономного редактора или указанный `article_id`. Не заменять художника Cloudflare FLUX / экспериментальным Gemini-контуром. Не выполнять фоновую работу без действительного запуска.

Сначала прочитай актуальный GitHub-документ `AfterDark1000/iipike-site/main/docs/AUTO_ARTIST_HANDOFF.md`. Для выбора материала изучи `editorial-intake/editorial_inbox/auto_drafts/*.json`, `editorial_inbox/auto_decisions/`, `editorial_inbox/auto_covers/` и `editorial_inbox/auto_cover_decisions/`.

## Условие допуска к обложке

1. `draft.status="ready_for_review"`, `draft.article_id` и `revision` определены; точный файл решения `auto_decisions/<article_id>-r<revision>.json` содержит `action="approve_text"` и `status="text_approved_cover_pending"`.
2. Git blob SHA **текущего** JSON черновика совпадает с `decision.draft_blob_sha`; `article_id`, `revision`, `updated_at` совпадают. При конфликте — стоп.
3. **Первым делом разбирай возвраты художнику.** Для каждой версии `vN` прочитай `auto_cover_decisions/<article_id>-r<revision>-vN.json`. Если статус `cover_revision_requested`, а следующей версии ещё нет, задание — сделать **vN+1**, взяв дословно `note` главреда. Варианты от v1 до v5, без пропусков. Ни существующие кандидаты, ни отвергнутые WebP, ни решения не перезаписывай. Если версия ждёт решения — не перерисовывай её самовольно. Если ни одной доработки нет, выбирай наиболее раннее утверждение `decided_at`, затем `pool_sequence`; у материала с `auto_handoff` ничего не создавай.
4. Все факты и художественный бриф читаются из реального текста, не из одного названия статьи.

## Исполнение

Создай оригинальную 16:9 обложку **своим штатным генератором ChatGPT**, по существующему визуальному стандарту. Не создавай стандартный FLUX-баннер и не копируй неудачную картинку с псевдотекстом. Визуально проверь сгенерированный результат, корректный русский заголовок, историю и антиповторы. При явном дефекте допустима одна целевая коррекция.

Создай **реальный WebP** 16:9 (желательно 1600×900; до 800 КБ), доказательно сохрани байты в GitHub в ветку `editorial-intake` по пути `editorial_inbox/auto_covers/<article_id>-r<revision>-v<version>.webp`. Первой версии — v1; после документированного возврата v1 — v2, затем v3 и т. д. Подтверди blob SHA и фактический размер. Невозможность передать реальные байты — блокировка, а не фиктивная готовность.

**Только после** успешного сохранения настоящего файла создай JSON `editorial_inbox/auto_covers/<article_id>-r<revision>-v<version>.json` по точной схеме и проверке `scripts/check_auto_cover_pilot.py`: `schema_version`, `article_id`, `text_revision`, `text_updated_at`, `source_draft_blob_sha`, `source_decision_blob_sha`, `status="ready_for_cover_review"`, `image_path`, `image_blob_sha`, `width`, `height`, `concept`, `headline`, `artist_notes`, `created_at`.
Перечитай оба файла. Не использовать картинки из экспериментального раздела.

**До отдельного утверждения главреда:** НЕ создавать `editorial_inbox/stories/<id>.json`, `editorial_inbox/covers/<id>.webp`, не писать в `main/news.json`, не запускать выпускающий workflow, Дзен или соцсети; не выставлять `approve_cover` или `editor_approved`. Отдать кандидата в `/admin/auto-editor/` для просмотра, затем ждать отдельного решения.

## Первый текущий сюжет

`avtor-virusnykh-rolikov-trollit-ii-rekruterov-kro-b0f0e86e2a184d00`, ревизия 3: постановочный скетч про человека с кроссовком на голове и вымышленного ИИ-интервьюера. Действующие файлы всегда важнее этой заметки. Не выдавать постановку за реальную запись Burger King.

## О расписании

Этот навык **не включает автоматический вызов личного плагина из GitHub Actions** и не создаёт новую ChatGPT scheduled task. Нельзя заявлять, что редакционный workflow запустил именно тебя, только потому, что появилась запись. При действительном запуске ты можешь взять уже утверждённую работу из GitHub.

## Доработки: пример настоящей записи из GitHub

Для статьи `avtor-virusnykh-rolikov-trollit-ii-rekruterov-kro-b0f0e86e2a184d00` версия текста r3 **утверждена**, но обложка v1 уже отклонена владельцем 18 ноября 2026. Прочитай `editorial_inbox/auto_cover_decisions/avtor-virusnykh-rolikov-trollit-ii-rekruterov-kro-b0f0e86e2a184d00-r3-v1.json` в `editorial-intake`. Подтверждённые замечания: «Почему он голый?», «Выбери другой стиль», «Надпись на картинке ни о чем не говорит про смысл статьи». Это **задание v2**, а не повод заново сохранять v1.

Персонаж одет, стиль и пространственная композиция заметно отличаются от v1, заголовок объясняет **постановочный скетч о человеке, испытывающем вымышленного ИИ-рекрутера**, а не просто наличие кроссовка. Не приписывай Burger King реальный найм через ИИ. Сохрани только отдельные `...-r3-v2.webp` и `...-r3-v2.json`; исходная версия и её отклонение остаются на месте. После сохранения предложи проверить новую версию в `/admin/auto-editor/`, не утверждай её за главреда.

Если защищённый сайт/Worker ещё не принимает v2, честно скажи о блокировке утверждения и не выдавай успешное сохранение файла за принятие новой версии.
