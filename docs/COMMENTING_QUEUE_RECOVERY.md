# Резервный запуск очереди Gemini

Штатный cron сборщика остаётся `7,37 * * * *` UTC. Резерв принимает успешное завершение `HPII — watchdog (no publishing)` в этом репозитории на `main`, когда сам watchdog запущен по `schedule` или `workflow_dispatch`. Самостоятельный плановый watchdog 19 ноября завершился в 17:56:54 по Екатеринбургу во время перерыва в обновлении очереди Gemini. Watchdog, запущенный после другого workflow, относится к другой цепочке и исключён. GitHub допускает не более трёх последовательных переходов `workflow_run`. В рабочем резерве один такой переход. [Самостоятельный запуск watchdog](https://github.com/AfterDark1000/iipike-site/actions/runs/44528567444) · [Пример запуска в цепочке](https://github.com/AfterDark1000/iipike-site/actions/runs/44510940314) · [Правила GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_run)

GitHub фильтрует `workflow_run` по имени, ветке и типу события. Первоначальный триггер watchdog проверяется условием задания. Для завершений из цепочек GitHub может создавать записи со статусом «пропущено». Они обходятся без runner и не занимают блокировку сборщика. Если GitHub задерживает оба cron, автоматический резерв также может опоздать. Доступен ручной запуск сборщика.

`update-queue` сериализует чтение, генерацию и запись в одной группе `hpii-commenting-queue`. При свежем снимке резерв заканчивается до чтения RSS и Gemini. Если `updated_at` старше 90 минут, перед генерацией он регистрирует статус `hpii/commenting-recovery-attempt` на точном коммите `commenting-data`. Этот статус отмечает попытку, исход виден в связанном run. Повторное событие для того же коммита пропускается, даже если первая попытка не записала JSON. При ошибке регистрации сборщик не стартует. Следующий коммит данных снова допускает резерв после порога. Для записи статуса право `statuses: write` есть только у `update-queue`.

Это задание берёт код из `main`, запускается только на `main` и пишет прежний `commenting/queue.json` в `commenting-data`. На push и PR работают офлайн-тесты. Сохраняются существующие лимиты сборщика — до трёх статей на запуск и 24 попыток в день по сохранённому `usage`. Ошибка XML МК остаётся локальной для источника. При повторении диагностика сохранит строку и позицию, сообщённые парсером.

После утверждённого слияния этого хотфикса запустить `commenting-queue.yml` вручную один раз на `main`. Проверить завершение `update-queue` со статусом `success`, продвижение `commenting-data` и новое значение `updated_at` в JSON. Затем проверить этот же снимок на открытой браузерной странице «Первого вагона». Превью должно показать новое время и отобрать материалы за последние 24 часа.
