# ХПИИ — приватная статистика Метрики и Вебмастера

Сборщик: `scripts/yandex_analytics_collect.py`. GitHub Actions: `.github/workflows/yandex-private-analytics.yml`.
**Ничего не публикует на iipike.ru, не изменяет статьи и не отправляет данные в публичные GitHub-репозитории.**

## Один раз настроить доступ

1. В аккаунте **AfterDark1000** создайте **НОВЫЙ приватный** репозиторий с точным именем `iipike-analytics` на [github.com/new](https://github.com/new). Включите **Private** и **Add a README** — чтобы появилась ветка `main`. Скрипт **не** будет писать в публичный `iipike-site` или в чужой приватный проект `kot-bayun-wp`.
2. В [Яндекс OAuth](https://oauth.yandex.ru/) создайте приложение «ХПИИ — аналитика» и выдайте разрешение **`metrika:read`** (только чтение Метрики). Для Вебмастера потребуется **`webmaster:hostinfo`** для просмотра данных сайта. Документация авторизации Вебмастера также описывает `webmaster:verify` для операций проверки прав — для сборщика оно не нужно. Используйте аккаунт с доступом к счётчику и с подтверждённым сайтом `iipike.ru` в Вебмастере. При необходимости создайте два OAuth-приложения и два токена.
3. Получите токен(ы) по официальной инструкции Яндекса. **Никогда не присылайте токены в ChatGPT и не добавляйте в код, JSON, PR, README или Issues.**
4. В [секретах Actions репозитория сайта](https://github.com/AfterDark1000/iipike-site/settings/secrets/actions) создайте:
   - `YANDEX_METRIKA_TOKEN` — OAuth с `metrika:read`.
   - `YANDEX_WEBMASTER_TOKEN` — OAuth с `webmaster:hostinfo`. Может совпадать с предыдущим при наличии обоих разрешений.
   - `HPII_PRIVATE_STATS_TOKEN` — **fine-grained GitHub PAT**, разрешённый **только** для нового `AfterDark1000/iipike-analytics`, с `Contents: Read and write` и стандартным `Metadata: Read`. Токен нужен лишь чтобы GitHub Actions мог записать файлы в *другой* приватный репозиторий. По окончании срока действия обновите его.
5. Если счётчиков для домена несколько, задайте `YANDEX_METRIKA_COUNTER_ID` в [Actions variables](https://github.com/AfterDark1000/iipike-site/settings/variables/actions). Это **не секрет**. Если счётчик один, поиск по домену автоматический.
6. Запустите **Actions → HPII — private Yandex analytics (NO PUBLICATION) → Run workflow**. Без токенов запуск напишет `NOT_CONFIGURED` и ничего не загрузит. При ошибке OAuth/отсутствии сайта вместо нулей будет сообщение с причиной. Токены никогда не выводятся.
7. В приватном репозитории появятся `reports/latest.json` и `reports/YYYY-MM-DD.json`. Собираются **7 и 30 последних завершённых дней** в часовом поясе `Asia/Yekaterinburg`; данные обновляются каждые 6 часов, исторические файлы обновляются для соответствующей даты.

## Как ChatGPT получит статистику

В подключении GitHub к ChatGPT необходимо разрешить доступ **именно к новому приватному репозиторию `AfterDark1000/iipike-analytics`**. Если используется режим «Selected repositories», добавьте его в установку GitHub App (это отдельное действие от создания PAT). После этого по запросу «ХПИИ, проверь Метрику и Вебмастер» ChatGPT сможет читать `reports/latest.json` через подключённый GitHub. Можно затем настроить понедельничный отчёт отдельной задачей.

## Что собирается

- Метрика: 7/30 дней `visits/users/pageviews`, дневная история, источники трафика, страницы входа по визитам, **популярные страницы по реальным просмотрам**. Только агрегаты, без IP, cookie или идентификаторов посетителей.
- Вебмастер: история поисковых показов, кликов, средних позиций и количества страниц в поисковой выдаче. Сборщик **не** отправляет сайт на переобход и не подтверждает права на управление сайтом.
- Если один сервис не подключён, его статус явно помечается `missing_credentials` или `error`. **Пустые данные не маскируются под нулевую посещаемость.**

## Важные условия

- Для **Метрики нужен действующий счётчик, реально установленный на `iipike.ru`**. Если на сайте ещё нет кода счётчика, его надо разместить отдельно после получения ID; до этого статистика не появится задним числом.
- Для **Вебмастера** необходима запись `iipike.ru` в аккаунте с подтверждёнными правами.
- Данные о показах канала Дзена в эту схему **не входят** — это другие отчёты.
- GitHub Actions cron — *приблизительное* расписание, возможны задержки; API Яндекса может показывать данные с лагом.
- Токены Яндекса имеют срок действия и могут потребовать обновления; следите за сообщениями `HTTP 401/403`.
