# «Новости коротко» — отдельный формат ХПИИ

## Назначение
Поштучные текстовые заметки (180–650 символов основного текста) с собственным заголовком, постоянной ссылкой, временем выхода и первоисточником. Нет обязательной картинки и искусственного расширения до полной статьи. Общие тематические дайджесты могут существовать отдельно; этот формат не собирает разные сюжеты в одну публикацию.

## Публичные адреса
- `https://iipike.ru/briefs/` — лента;
- `/briefs/<slug>/` — отдельная статическая страница каждой **утверждённой** записи;
- `/briefs/feed.xml` и `/briefs/sitemap.xml` — независимые RSS и sitemap;
- блок «Новости коротко» на главной, но не в четырёх существующих рубриках.

## Отбор и источник истины
- `data/briefs/candidates.json` — отдельная очередь возможных коротких записей, **не публичная публикация**. Существующие пункты пула сохраняются, не удаляются и не превращаются в `approved` автоматически.
- `data/briefs/approved.json` — единственный вход для публикации. Первоначально пуст.
- Каждая публикация требует **реального отдельного решения главреда**. В GitHub создаётся Issue с названием `ХПИИ: утвердить короткую новость <slug>` от владельца AfterDark1000; тело содержит проверенный заголовок, исходный URL и строку `SHA256: <digest>` точной редакции текста (функция `scripts/build_briefs.py:approval_sha256`). Затем подтверждённый материал переносится в approved.json с неизменными текстом, заголовком, ссылкой и ID из кандидата, с метками `status=editor_approved`, `approved_by=human_editor`, `approval_ref`, `approved_at_utc` и `published_at_utc`.
- Сам JSON approval **не эквивалентен доказательству**: workflow `hpii-briefs.yml` отдельно читает Issue через GitHub API и сверяет автора, заголовок, первоисточник и хеш точного текста, прежде чем создавать публичную страницу.
- На главной и в ленте ни один pending_review не появляется. Если обсуждение не проверено или источник сомнительный — оставлять в кандидатах или закрыть, не публиковать «лишь бы не пропало».

## Независимый релиз
Workflow `hpii-briefs.yml` отдельно проверяет записи на push и дважды в час по своему расписанию, а также поддерживает ручной dispatch. Скрипт `scripts/build_briefs.py --write` изменяет только `briefs/*` и короткий блок `index.html`. Запись Git в main только fast-forward, без force; конфликт пережидает следующий запуск. Сайт может развернуться позже, чем GitHub-коммит — проверяй Pages отдельно. Он никогда не создаёт записи в `news.json`, `editorial_inbox/stories/`, `editorial_inbox/covers/`, Дзен, Threads/X или часовом site-first планировщике.

Тесты: `python3 -m unittest discover -s tests -p test_briefs.py -v`; `python3 scripts/build_briefs.py --check` для проверки итоговой статической версии.

После успешной генерации страниц workflow автоматически и идемпотентно закрывает свободный исходный `pool_id` как `approved`, ставит `article_id=<slug>` и записывает ссылку в `note`; уже занятый сюжет не перезаписывает. До первого выпуска эти три кандидата всё ещё `queued`: редактор больших статей не должен их брать. Перед выпуском проверять дубль с `news.json`.

Режим утверждения через публичную страницу `/admin/briefs/` пока read-only: кнопка автоматического подтверждения без реальной серверной записи запрещена. Технический штаб помогает оформить и связать Owner Issue и утверждённый JSON. Следующий этап — расширить защищённый OAuth-пульт, если этот формат покажет пользу.

## Отдельный редактор
Инструкция отдельного чата: [BRIEFS_EDITOR_AGENT.md](BRIEFS_EDITOR_AGENT.md). `fact_check` — служебное поле кандидата, показывается только свёрнутым в админке; публичные страницы берут исключительно утверждённые `headline`, `body`, `source_url` и метаданные. Изменение точного текста после утверждения меняет SHA256 и блокирует выпуск.

## Разделение двух ручных чатов
- `docs/BRIEFS_MORNING_TRIAGE_AGENT.md` — утренний сортировщик **только по команде главреда**: полный просмотр свободного пула, рекомендации «полная / короткая / отложить / отклонить», без записи и резервирования.
- `docs/BRIEFS_EDITOR_AGENT.md` — уже существующий редактор коротких новостей: пишет только отобранные или явно порученные тексты, проверяет источники и передаёт на утверждение, не заменяет сортировщика.
- Ни одна рекомендация сама по себе не меняет статус в `data/site_news_pool.json`. Перед работой редактор перечитывает запись, чтобы исключить гонки с основным редактором. Новые автоматические задачи не создаются.
