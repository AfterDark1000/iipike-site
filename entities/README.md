# Каталог компаний и продуктов ХПИИ

Публичный раздел: /entities/. Генератор: scripts/site_entities.py. Источник привязок:
data/entity_registry.json — редакционно проверенный список ID уже опубликованных новостей.

- Раздел использует **статические HTML**, существующий news.json и локальные SVG.
- Одно событие может относиться сразу к двум компаниям и продукту.
- **Автоматический поиск по полному тексту отключён**: случайные упоминания не создают тег.
- Сейчас справочник содержит **ручную выборку**, а не весь архив. Новые статьи не
  получают компанию/продукт без отдельного редакционного решения.
- Любая новая компания или продукт добавляется в JSON по разрешённому ключу
  после проверки принадлежности новости и ссылки на существующий ID. Для продукта
  обязательно существующая компания-владелец.
- Для обновления: \`python3 -m scripts.site_entities\`, затем
  \`python3 scripts/build_sitemap.py\`, проверки \`--check\` и полноценные CI-тесты.
- Изменение одного лишь текста статьи или пересказа новости **не меняет** таксономию.

Это первая публичная стадия. Автоматическую передачу **явно выбранных** меток
из редакционного входящего JSON в news.json добавлять только после
отдельной проверки протокола публикации и точных регрессий. Не включать
эвристическое «распознавание всех упоминаний» в новостном конвейере.

Изображения брендов перенесены из \`lab/entities/icons/\`, атрибуция и MIT
сохранены в \`lab/entities/ICONS.md\` и \`lab/entities/ICONS-LICENSE.txt\`.

## Метки внутри статей

На страницах опубликованных статей, входящих в проверенный справочник,
под темами выводятся компактные ссылки на компании и продукты с локальными SVG.
Список строится только из `data/entity_registry.json`;
Dzen Markdown, тело статьи, даты, обложки и блок «По теме» не меняются.
Рендерер `render_article` добавляет те же метки при штатной пересборке.
Для старых HTML применяется безопасное `inject_article_entity_nav` с проверкой
неизменности всего HTML от `<figure class="cover">` до конца страницы.

Если статья не отмечена в справочнике, никакая метка не появляется.

## Архивная разметка (11.11.2026)

Проверены заголовки и краткие описания **274** опубликованных материалов.
Ручной справочник содержит **61 компанию** и **24 продукта**; у **195**
публикаций есть хотя бы одна главная сущность, остальные сознательно остаются
без метки, когда нельзя корректно выбрать главного участника. Одна новость может
попасть в несколько подборок.

Для масштаба каталог отсортирован по названию и снабжён локальным фильтром
(`assets/entity-search.js`). Там, где подходящий открытый логотип был
доступен, он сохранён как статический SVG (Lobe Icons / Simple Icons);
остальные символы — оригинальные двухбуквенные монограммы, не официальные
логотипы компаний. Без сторонних CDN.

Разметка ранее опубликованных страниц обновлена только в заголовочном блоке.
Одобренные редакционные JSON и Markdown, тексты статей, иллюстрации, дата
публикации, RSS и очередь не изменялись. Для **новых** статей редактор явно выбирает ключи `companies` и `products` в
`editorial_inbox/stories/<id>.json`; штатный публикационный конвейер добавляет
их к справочнику при выпуске статьи. Старые утверждённые материалы не
переразмечаются автоматически, анализ текста и догадки запрещены.

## Передача от редактора (11.11.2026)

Два массива ключей, не отображаемых названий: `"companies": ["google"]`,
`"products": ["gemini"]`. Пустые `[]` допустимы. Каждый ключ должен уже
существовать в этой версии справочника. Владелец выбранного продукта
добавляется автоматически. Входящий JSON сохраняется только в
`editorial-intake`; публичный реестр, страницы сущностей и значки
создаются **вместе с обычным выпуском статьи** на проверенной релизной ветке.
Прошлые 195 размеченных публикаций не пересчитываются по тексту.

Если новый продукт/компания отсутствует, сначала отдельное контролируемое
расширение справочника с локальным SVG и тестами; не открывать для неизвестной
метки URL наугад.
